# Карьерный консультант — ИИ-агент, который ведёт кандидата по платформе

Статус: **ТЗ v1, 9 октября 2026**. Ведёт Иван Ветров. Замечания команды —
до начала фазы 2 (модель данных). Основание — [концепция продукта](product-concept.md)
(профиль с доказательствами, идея I07) и [требования](requirements.md)
(загрузка резюме с распознаванием, опрос по специализации, выбор грейда,
PDF-профиль, объяснимость подбора). Стек — [stack.md](stack.md).

## Зачем

Кандидат не заполняет формы — он разговаривает с консультантом: присылает
резюме, ссылки, документы, отвечает на вопросы и получает профиль из
утверждений с цитатами-источниками, предложение теста, план «чем доказать»,
задания на пробелы и вакансии, где его профиль закрывает потребность.
Консультант остаётся с ним и дальше: после теста, после приглашения, при
выборе следующего шага. Форма остаётся запасным путём.

Для жюри это самый заметный момент пути кандидата и одновременно
демонстрация разбора резюме, объяснимого подбора и честного обращения с
данными: цитата у каждого утверждения, ничего не попадает в профиль без
клика кандидата.

## Границы

| Агент может | Агент не может | Почему |
| --- | --- | --- |
| Читать всё присланное: файлы, любые URL, профили GitHub / Codeforces / ФСП (демо-источник) | Писать в профиль напрямую | Профиль — только через подтверждение кандидата |
| Предлагать утверждения с цитатой из источника | Присваивать категорию или грейд | Категория — только по тесту (ТЗ) |
| Рекомендовать тест, задания, вакансии | Откликаться, писать работодателю | Действия с последствиями — за человеком |
| Задавать уточняющие вопросы, вести диалог «что дальше» | Менять уровень доказанности | Уровень ставит код по типу источника |
| Показывать свои шаги и отброшенное | Делать HTTP-запросы в обход сборщика | SSRF, 152-ФЗ |

## Сценарии

1. **Первый вход.** После email и согласий кандидат попадает в чат. Присылает
   PDF и ссылки. Видит шаги: «читаю резюме… читаю github.com/x… нашёл 11
   утверждений, 2 отбросил — нет цитаты; в PDF скрытый текст, проигнорирован».
   Карточки «да / поправить / нет». Консультант предлагает специализацию и
   грейд как выбор теста и объясняет, что категорию даст только тест.
2. **После теста.** Карта пробелов к цели, 3 задания на пробел из банка, 3–5
   вакансий с «закрываешь 4 из 6, не хватает …». Цифры — только «по вакансиям
   на платформе».
3. **Свободный вопрос.** «Хочу в финтех-бэкенд» → план из 3 шагов.
4. **Приглашение.** Консультант объясняет покрытие потребности; принять или
   отклонить — кнопкой кандидата.
5. **Без истории ФСП.** Полный путь без штрафа; привязку предлагаем один раз.
6. **Инъекция в резюме.** «Найден скрытый текст, проигнорирован»; утверждение
   из него в профиль не попадает.

## Устройство

```text
Кандидат ⇄ Чат (Next.js, SSE) ⇄ Оркестратор (код)
                                    │
     Сборщик (код)  →  Извлекатель (LLM, JSON по схеме)  →  Проверяющий (код)
     файлы, URL,       текст → утверждения из                цитата есть в источнике?
     GitHub, CF, ФСП   закрытого каталога + цитата           ID в каталоге? уровень ≤ max
                                    │
     Консультант (LLM + инструменты)      Подбор (код, тот же матчер, что у работодателя)
                                    │
                    Профиль из утверждений — пишет только кандидат
```

**Инструменты консультанта:** `read_upload`, `fetch_url` (через сборщик с
фильтрами), `fetch_profile` (github / codeforces / stackoverflow / fsp-demo),
`catalog_search`, `propose_claims` (черновик карточек), `get_profile`,
`get_gap_map`, `recommend_test`, `recommend_tasks` (из банка,
детерминированно), `recommend_targets` (матчер), `explain_invitation`,
`start_verification`, `render_profile_pdf`, `ask_user`. Схемы — Zod; в модель
уходит только валидированное.

**Утверждение:** `claim_id` (только из каталога), формулировка, уровень
`self_reported | artifact | platform | third_party` (максимум по источнику
ставит код: резюме → со слов, GitHub → артефакт, ФСП/рейтинг после проверки
владения → третья сторона, тест/интервью → платформа), источник с цитатой и
координатами, ограничение вывода, чем доказать, статус
`proposed → confirmed | edited | rejected`.

**Данные (добавка к модели из [архитектуры](architecture.md)):** `Upload`,
`Source`, `ClaimCatalog`, `Claim`, `Conversation`, `Message`, `AgentRun`
(журнал вызовов: провайдер, модель, задержка, токены, валидность JSON),
`Recommendation`. Ложится на `CandidateProfile`, `CompetencyEvidence`,
`Achievement`.

**Каталог утверждений:** Backend и Frontend, по два грейда (Junior, Middle).
Черновик готовит агент, правит Иван. Это самая долгая ручная часть.

## Безопасность

| Угроза | Мера |
| --- | --- |
| Инъекция через резюме, README, страницу | Внешний текст — данные в отдельных блоках; у извлекателя нет инструментов, у консультанта нет записи; цитата + проверка кодом; флаг скрытого текста; тесты на атаки |
| SSRF через «любой URL» | Резолв DNS, запрет приватных и metadata-адресов, без редиректов на другой хост, таймаут, лимит размера, типы контента |
| Галлюцинация навыка | Закрытый каталог, обязательная цитата, уровень ставит код, подтверждение кандидатом |
| Чужой GitHub / Codeforces | Уровень «артефакт», проверка владения, защита в интервью |
| Чужие данные | Проверка владельца на каждом `candidate_id`; никаких тестовых аккаунтов с простыми паролями |
| 152-ФЗ | Только присланное о себе по согласию; чужие ПДн не извлекаем; маскирование контактов; модели в РФ |
| Сбой провайдера на демо | План В, кэш демо-кандидатов, очередь с позицией, таймаут |

## Не входит

Голос и аватар; симуляция работы под вакансию; автоотклики и переписка с
работодателем от имени кандидата; векторная память; исполнитель кода.

## Зависимости от команды

- Банк заданий и матчер: консультант рекомендует через них. Пока их нет —
  детерминированные заглушки на синтетике.
- Модель данных: сущности выше добавляются к [архитектуре](architecture.md);
  замечания — до фазы 2.
- Ключи LLM — на юрлицо/ИП Ивана.
