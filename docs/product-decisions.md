# Реестр продуктовых решений

Актуальность: **11 октября 2026 года, МСК.** Здесь — решения владельца продукта и команды, принятые и реализованные в `platform/`; детали механик живут в указанных документах и коде (один факт — в одном месте). ID в скобках (`H-`, `P-`, `A-`) — трассировка к идеям владельца, `R-` — к [требованиям](requirements.md). ADR: [0001](decisions/0001-auth-yandex-id.md), [0002](decisions/0002-grade-test.md), [0003](decisions/0003-three-stage-assessment.md), [0004](decisions/0004-role-switching.md), [0005](decisions/0005-consents.md), [0006](decisions/0006-evidence-profile-core.md), [0007](decisions/0007-stack.md). Открытые вопросы к организаторам — [decisions-and-questions.md](decisions-and-questions.md).

## 1. Ядро продукта

| Решение | Где |
| --- | --- |
| Обещание продукта: подтверждаем **умение сейчас**, а не прошлый опыт. Главная боль — работодатель не верит резюме и проверяет каждого сам; мы делаем проверку один раз и одинаково для всех, обратная механика строится поверх категории, которой верят | [ADR 0006](decisions/0006-evidence-profile-core.md) (H-09) |
| Профиль — список утверждений с уровнем доказанности, источником и датой; подбор — покрытие потребности работодателя доказательствами; объяснение выдачи следует из покрытия | ADR 0006; `server/claims`, `server/recommend` |
| Категория (направление × подкатегория × грейд) задаётся **только тестом**; созвон, проект и защита добавляют доказательства, категорию не меняют | [ADR 0002](decisions/0002-grade-test.md), [ADR 0003](decisions/0003-three-stage-assessment.md) |
| Порядок уровней доказанности: «проверено платформой» (тест, защита, созвон) выше «третьей стороны» (ФСП, референс); тест и защита поднимают «третью сторону» до «платформы» | `server/claims/levels.ts`, `server/recommend/weights.ts` |
| Затухание доказательства за 12 месяцев и потолок попыток — концепция, не код MVP; в коде есть дата доказательства и карта пробелов | ADR 0006 |
| Принципы: внешне просто, внутри сложно (P-01); каждая механика с измеримой валидацией и честными оговорками (P-02, P-03) | [validation-results.md](validation-results.md) |
| В цифрах валидации различаем «симуляцию агентом на персонах» и «проверку на людях»; людей не было, так и называем | validation-results.md |

| Пул демо-кандидатов нужен базе поиска работодателя и валидации, из БД не удаляется, из списка входа убран | `server/demo` |

## 3. Знакомство и консультант

| Решение | Где |
| --- | --- |
| Вход вместо анкеты: чат-консультант принимает резюме и ссылки, предлагает категорию и утверждения, ведёт к тесту. **Читает и предлагает свободно, в профиль пишет только после подтверждения кандидата** (H-10) | [career-consultant.md](career-consultant.md) |
| Знакомство и консультант — одна страница `/consultant` и один серверный маршрут; знакомство — таймлайн над чатом, который можно скрыть; незаполненное — подсказка «дополнить» в чате и в карточке «Что я о тебе знаю» | `app/(shared)/consultant`, `server/onboarding` |
| Свободный вопрос в любой момент знакомства: совпал с кнопкой — ответ на шаг, иначе отвечает консультант и возвращает к шагу. До согласия и выбора роли свободный ввод в модель не отдаётся | `server/onboarding` |
| Интерфейс чата: лента, варианты чипами, «Пропустить вопрос» над полем ввода (скрыта без вопроса), вложения и drag-n-drop, плавное появление реплик, стрим 45–110 зн/с, ввод прижат книзу, граница чата и сцены перетаскивается | `components/chat`, `components/consultant` |
| Персонаж — **Кира**, женский род, одна константа для кандидата и работодателя. Позиция «компаньон»: выжать максимум честного сигнала — искать незамеченные сильные стороны, учить доказывать артефактами, готовить к тесту; без приукрашивания и без подгонки заданий под человека | `lib/persona.ts`, `server/agent/prompts` |
| Работодателю — свой консультант с первого входа: другие промпты, тот же шаблон чата; после знакомства — помощник по подбору | `server/agent/employer` ([employer-assistant.md](employer-assistant.md)) |
| Память «Что я о тебе знаю» (ответы знакомства и факты из чата, правка и удаление); скиллы и инструкции кандидата (стиль и фокус советов, не влияют на выдачу работодателю) | `server/consultant/aside.ts` |
| Файлы и ссылки: PDF, DOCX, MD, TXT, CSV до 5 МБ; любой URL с SSRF-проверкой на каждом шаге редиректа; оригиналы в файловом хранилище пользователя; текст из файлов и страниц — недоверенный | `server/uploads`, `server/collector` |
| Инструменты агента: 18 = «14 из ТЗ + 4 служебных»; таблица соответствия — в материалах сдачи | [agent-prompting.md](agent-prompting.md) |
| Знание вместо перегруженного промпта: инструмент по документам платформы и поиск в интернете как крайний случай (результаты — недоверенный текст) | `server/agent/knowledge`, `server/agent/web-search` |
| Промпты по документации провайдеров; файл фактов платформы; проверка ловушками (выдуманные правила, инъекции, границы) | agent-prompting.md; validation-results.md |
| Голос: SpeechKit STT/TTS; без ключа — Web Speech API браузера с подписью «распознаёт браузер» (аудио уходит в Google, называем на защите) | `server/stt`, `server/tts` |
| Лицо консультанта — 3D wireframe-голова (three.js) по мотивам брендбука ФСП, плетение нитей; рот на морфах с висемами из спектра озвучки; слежение за курсором; запасной знак ФСП без WebGL | `components/avatar`, `components/head` |
| Правая колонка `/consultant`: голова, «Твой путь» (шаги и ссылки), документы, «Что я о тебе знаю», рынок («Кого ищут компании»); по высоте экрана без скролла на 13–16 дюймах | `server/consultant/aside.ts` |
| Языковая модель: российская по смыслу 152-ФЗ (данные не покидают РФ), провайдер сменный через адаптер; открытые модели — только Yandex Cloud или своё железо | [ADR 0007](decisions/0007-stack.md); [stack.md](stack.md) |

## 4. Профиль и утверждения

| Решение | Где |
| --- | --- |
| Каталог утверждений составлен человеком (веса, грейды); утверждения из чата попадают в профиль как «со слов» и повышаются тестом, созвоном, проектом, защитой, ФСП | `ClaimCatalog` в `prisma/schema.prisma`; ADR 0006 |
| Приватность до принятия приглашения: имя, почта, цитаты скрыты; показывается тип источника («доказано: GitHub» без ссылки) (R-C-16, R-E-07) | `server/employer/privacy.ts` |
| Контакт кандидата — поле знакомства; раскрывается только после принятия приглашения и согласия на раскрытие | ADR 0005 |
| Согласия: девять видов, отдельные неотмеченные галочки, отзыв без удаления, версия текста; тексты — черновик, юрист не проверял, оператор — заглушка | [ADR 0005](decisions/0005-consents.md) |
| ФСП: победа > приз > участие, уровень соревнования и давность не взвешиваем (совет организаторов); у кандидата без ФСП штрафа нет (R-FSP-03); достижения — нашей модели, данные синтетические | `server/employer/fsp-weight.ts`; `fsp-sim/` |
| Подсказка ФСП ID при знакомстве, привязка — выбор демо-профиля из симулятора реестра с пометкой «API ФСП не предоставлен» | `fsp-sim/README.md` |

## 5. Тест на грейд

| Решение | Где |
| --- | --- |
| Адаптивный тест по IRT на параметризованных генераторах заданий; защита после теста — флаг, не отнимает грейд | [ADR 0002](decisions/0002-grade-test.md); `server/test` |
| Отдельный тест на подкатегорию: категория = направление × подкатегория × грейд; четыре направления (backend, frontend, ИИ, инженерия), 17 подкатегорий | [ADR 0003](decisions/0003-three-stage-assessment.md), дополнение 10.10; `server/directions.ts` |
| Грейды Junior, Middle, Senior; Senior — сверх ТЗ, так и называем в документе сдачи. Пороги по θ: Junior −0,7, Middle −0,1; подтверждение при вероятности не ниже 0,8 (в пользу работодателя) | `server/test/policy.ts` |
| Не сдал Middle — подтвердить Junior в один клик по той же попытке, по согласию; дозадавание Junior-заданий (`junior_probe`) и при заявке Junior | ADR 0002 |
| Интервалы пересдачи 30 и 14 дней, в демо минуты | ADR 0002 |
| Пул — не менее 14 семейств заданий на подкатегорию (6 Junior, 4 Middle, 4 Senior) | ADR 0003, дополнение 16:15 |
| Индекс честности (A+B+D): превышение таймера не считается группой для высокого риска; серия верных быстрее 10 % лимита — высокий риск; подтверждающий тест требует согласованности θ исходной и подтверждающей частей. По симуляции на персонах | `server/test/integrity.ts`; ADR 0003, дополнение 11.10 |
| Тест остаётся «классическим» для жюри как предварительная калибровка; грейд подтверждают созвон, проект, защита. Автоматически грейд не понижаем | ADR 0003 |
| Главная цифра критерия 2 — 8 персон с профилями знаний; θ-синтетика — границы чувствительности и проверка утечки; ложный Junior у слабой персоны около 12 % — называем числом | [validation-results.md](validation-results.md) |

## 6. Проекты, защита, созвоны

| Решение | Где |
| --- | --- |
| Три ступени: созвон → проект → защита проекта; результат ступеней — доказательства и картина для работодателя | [ADR 0003](decisions/0003-three-stage-assessment.md) |
| Ступень 1: квалифицирующий созвон внутри `/consultant` (режим звонка: аватар сверху, текст реплики снизу, микрофон, запись); 4–6 вопросов по специализации и резюме; **отдельный слепой оценщик** по рубрике (глубина, «почему так», граница знаний, доведение, 0–2); результат — карта глубины | `server/call`, `server/interview` ([competency-model.md](competency-model.md)) |
| ИИнтервью — тот же механизм звонка (другой вид сессии), доступен после теста; кнопка звонка активна только когда есть о чём говорить; повтор того же вида — не чаще раза в 24 часа (демо-кандидатов не ограничиваем) | `server/call/readiness.ts` |
| Ступень 2: работодатель выбирает базовый шаблон (направление × подкатегория × грейд), задаёт критерии и пожелания; ИИ переписывает **только легенду** под домен работодателя; скрытые тесты и контракт общие, поэтому кандидатов разных работодателей проверяют одинаково (R-T-02) | `server/project`; [project-templates.md](project-templates.md) |
| Проект — синтетический шаблон платформы, не реальная задача работодателя (бесплатный труд, R-X-01); ИИ разрешён явно, журнал работы с ИИ обязателен | project-templates.md |
| Автопроверка: скрытые тесты и статанализ дают балл; LLM-рубрика по пожеланиям — пояснение и флаг, не балл. Песочница — отдельный сервис `runner` в изолированном контейнере | [platform/runner/README.md](../platform/runner/README.md) |
| Выдача проекта — **лента обезличенных заданий до приглашения** (без компании и зарплаты); это не оффер, а задание; компания и вилка раскрываются в приглашении на защиту | ADR 0003, дополнение 10.10 |
| Ступень 3: защита проекта, ведёт ИИ голосом с аватаром; вопросы строятся из кода и коммитов кандидата; порог 5 из 8; слабая защита при сильном проекте — **флаг работодателю, не понижение**; вердикта «фейк» автоматом нет (ст. 16 152-ФЗ) | `server/defense`, `server/defense-room`; [validation-stages.md](validation-stages.md) |
| Работодатель может подключиться к защите живьём, «замьютить ИИ» и говорить сам; аудио — WebRTC P2P, текст как запасной канал; вопросы после защиты копятся и задаются при следующем входе | ADR 0003; `components/call/useRtcAudio.ts` |
| Запись: транскрипт и аудио кандидата, отдельное согласие перед первым созвоном; работодатель видит запись только после принятого приглашения, в подборке — оценки и флаги | ADR 0003, [ADR 0005](decisions/0005-consents.md) |
| Созвон и проект — сигнал работодателю и вес в ранжировании, не грейд | ADR 0003; validation-results.md |
| Ответ созвона: озвучка по предложениям, стриминг ответа модели | `server/call/stream.ts` |

## Отклонено / заменено

| Что | Причина |
| --- | --- |
| Формула ФСП «уровень × место × масштаб × давность» | организаторы советуют не взвешивать уровень и давность |
| Многодневный сеттинг на 3–7 дней до приглашения (H-08) | заменён ступенями ADR 0003 (созвон, проект 2–4 часа, защита) |
| Одна «имитация команды» как вход в базу (H-03) | жюри проходит сквозной путь за минуты; роль имитации взял проект под работодателя |
| Один мини-проект на категорию | слишком широко для оценки навыков; проект привязан к шаблону подкатегории и грейда с легендой работодателя |
| Автопроверка проекта через GitHub Actions | заменена песочницей `runner` |
| Адаптивное интервью как механика грейда | критерий 2 требует воспроизводимой оценки; интервью — подтверждающий слой |
| Фотореалистичный видео-аватар по умолчанию | не проходит по ТЗ целиком и дорог; по умолчанию открытый 3D-аватар |
| Alice AI LLM как модель агента | не вызывает инструменты в живом агенте |
| `deepseek-v4.1-flash` вместо `deepseek-v4-flash` | хуже по ловушкам и матрице инструментов, медленнее |
| Локальная модель | нет GPU, 16 ГБ |
| Порог рекомендации Middle 0,6 и 0,4 | заменены пересмотром по доле покрытия от всей сигнатуры |
| Автоматическое понижение грейда по сигналам | ст. 16 152-ФЗ; сигнал и подтверждающий тест вместо понижения |
| Отдельный экран «Регистрация кандидата» и режим «Вернуться к знакомству» | знакомство слито в единый вид консультанта |
| Демо-аккаунты на `/auth` | вход на проде — только по почте и Яндекс ID |
| ИИнтервью отдельной страницей | внутри режима звонка; `/interview` остаётся страницей результата |
| Отказ от редиректов в сборщике ссылок | разрешены с повторной SSRF-проверкой каждого шага |
| Приём фото и Excel в чат | только PDF, DOCX, MD, TXT, CSV |

## Открыто

| Что | Почему |
| --- | --- |
| Зарплатные ожидания кандидата в подборке не участвуют, хотя знакомство о них спрашивает (R-M-03) | фильтр по пересечению вилок или убрать обещание |
| Показ связки «вакансия → задания и тесты» (R-T-04) | документ есть, наглядный показ — по времени |
| Верификация компании (R-D-05) | заявлена только ИНН-метка «демо» |
| Выбор газетного шрифта заголовков с кириллицей | вопрос по дизайну команды |
| Грейд по созвонам и проекту (вместо только сигнала) | ADR после сдачи |
| Гипотезы без реализации: режим работы как третья ось (исполнитель, тимлид, соло-инженер), сеттинг из интервью с работодателем | концепция |
| Пилот на людях школы и экспертная разметка записей интервью | заморожено по сроку; калибровка делается персонами |
| Свободные вопросы работодателя в знакомстве | отложено до подключения помощника |
| Проверка ложных высоких оценок индекса честности на людях | только симуляция на персонах |
