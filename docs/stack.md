# Стек

Статус: **принят 9 октября 2026 года** (Иван Ветров ведёт серверную часть и
агента). Заменяет раздел «Вариант стека» в [архитектуре](architecture.md).
Текущий [мокап](prototype.md) — импорт предоставленных HTML/CSS/JS-страниц в
`site/` без npm-зависимостей; переход рабочего приложения на стек ниже — следующий шаг.

## Выбор

| Слой | Решение | Почему |
| --- | --- | --- |
| Рантайм | Node.js 24, TypeScript 5 | Один язык на сервере и в интерфейсе |
| Веб и API | Next.js 15 (App Router, route handlers), React 19 | Кабинеты и API в одном приложении; `output: 'standalone'` — штатная сборка для Docker |
| Валидация | Zod 4 | Одни схемы для API, форм и ответов LLM |
| Данные | Prisma 6, PostgreSQL 16; pgvector — только если понадобится векторный поиск | Миграции и типизированные запросы; модель данных — в [архитектуре](architecture.md) |
| LLM | `openai` SDK 6 через OpenAI-совместимый адаптер; провайдер в конфигурации | Провайдер меняется без правки кода |
| Файлы кандидата | unpdf (PDF), mammoth (DOCX) | Чтение резюме и документов в чате консультанта |
| PDF профиля | Печать из браузера; серверный PDF (Puppeteer) — при наличии времени | Без Chromium в контейнере по умолчанию |
| Почта | Mailpit с веб-ящиком на демо | Письма подтверждения видны жюри без внешней доставки |
| Тесты | Vitest + Testing Library (модули, компоненты, API), Playwright (сквозные сценарии) | Связка из официальной документации Next.js; async Server Components проверяются только сквозными тестами |
| Запуск | Docker Compose: `app`, `db`, `mailpit`; обратный прокси с HTTPS — на стенде | Один `docker compose up` |

Готовые части (цикл агента с инструментами, чтение ссылок с защитой от
внутренних адресов, разбор PDF/DOCX, подтверждение email, генерация PDF)
переносятся из рабочих проектов Ивана на тех же версиях библиотек.

## Языковая модель

Требование: **персональные данные не покидают РФ** (152-ФЗ). Подходят
YandexGPT/Alice AI (Yandex AI Studio), GigaChat, а также открытые модели,
размещённые в РФ (например, в Yandex Cloud). Зарубежные API для данных
кандидатов не используем. Конкретная модель выбирается по качеству и
поддержке вызова инструментов; первая проверка — пробный запрос с одним
инструментом. Если вызов инструментов не работает, модель отвечает строгим
JSON по схеме Zod, а шаги выполняет код.
