# Живая разметка теста на грейд: 1 час, 2–3 человека

Зачем: параметры заданий (`irtA`, `irtB`) и пороги грейдов в
[ADR 0002](decisions/0002-grade-test.md) сейчас экспертные (поставлены агентом) и
не оценены на людях. Эта процедура даёт первую привязку к реальной шкале и
согласие экспертов; результат — обновлённые `irtB` в `TaskTemplate` с пометкой
`paramsSource = calibrated` и раздел в
[validation-results.md](validation-results.md).

## Кто и сколько

Владелец + 1–2 человека, знающих Backend/Frontend на уровне Middle+. По 30–40 минут
на человека, независимо друг от друга (вслепую: не обсуждать до сдачи листов).

## Шаг 1. Выгрузить по одному экземпляру каждого шаблона (5 минут)

```bash
cd platform
npx tsx -e "
import { GENERATORS } from './src/server/test/generators';
for (const g of GENERATORS) { const i = g.generate(12345);
  console.log('\n### ' + g.id + ' (' + g.specialization + ', ' + g.grade + ')\n' + i.prompt + '\n\n```\n' + (i.code ?? '') + '\n```\nОтвет: ' + i.answerKey); }
" > /tmp/calibration-items.md
```

Отдать каждому эксперту файл **без ответов** (вырезать строки `Ответ:`) — 24 задания.

## Шаг 2. Лист эксперта (30 минут)

Таблица на каждого, по строке на шаблон:

| id | Решил сам (да/нет, минуты) | Доля Junior, которые решат, % | Доля Middle, которые решат, % | Задание неоднозначно? (что) |
|---|---|---|---|---|

Правила Angoff: представить 100 «минимально достаточных» Junior и 100 «минимально
достаточных» Middle; оценить, сколько из каждой сотни ответят верно. Не обсуждать.
Файл: `platform/eval/test/calibration/<имя>.csv` (столбцы `id,solved,minutes,pJunior,pMiddle,note`).

## Шаг 3. Пересчёт (10 минут)

1. Согласие экспертов: ранговая корреляция (Кендалл τ) по `pMiddle` между парами; цель
   τ ≥ 0,5. Ниже — обсудить расходящиеся шаблоны, переформулировать условие, не менять
   параметры «на глаз».
2. Новое `b` шаблона: из медианы `pMiddle` при θ = 0,6 (центр Middle) и `pJunior` при
   θ = −0,8: `b = θ − ln(p/(1−p))/a` по обеим точкам, среднее; `a` оставить, если обе
   точки дают близкие `b` (разница ≤ 0,5), иначе `a` = разница логитов / 1,4.
3. Записать в БД и пометить:
   ```sql
   UPDATE "TaskTemplate" SET "irtB" = <b>, "irtA" = <a>, "paramsSource" = 'calibrated' WHERE id = '<id>';
   ```
   Сид (`npm run db:seed`) калиброванные значения не перетирает.
4. Пороги: `GRADE_CUT` в `src/server/test/policy.ts` — средняя точка между медианными
   θ, при которых по новым `b` «минимально достаточный» Junior/Middle решает половину
   заданий своего уровня. Изменение порогов — новая версия `POLICY_VERSION`.
5. Прогнать `npx tsx eval/test/run.ts --n 2000` с новыми параметрами из кода
   (скрипт читает параметры из реестра генераторов: временно внести калиброванные `a`, `b`
   в `generators/*.ts` или добавить чтение из CSV) и обновить таблицы в
   `validation-results.md`, сменив оговорку «экспертные» на «калиброваны на N экспертах».

## Шаг 4. Живые прогоны (по желанию, 20 минут)

Каждый эксперт проходит тест на стенде дважды (`TEST_DEMO_INTERVALS=true`), записывает
исход, θ̂ и время. Это иллюстрация для документации и слайда, не статистика.

## Что не делать

Не подгонять `b` под результаты симуляции и не менять параметры после сдачи 11.10.
Решённые на людях расхождения фиксировать в `validation-results.md`, а не молча.
