# eval/matching — оценка подбора кандидатов работодателю

Без БД и сети. `npx tsx eval/matching/run.ts` (флаг `--no-write` — только таблица) печатает таблицы и дописывает `results.json`.
Скрипт читает `src/server/employer/ranking.ts` как есть: после правок весов достаточно перезапустить.

## Два набора, считаются отдельно

| Набор | Состав | Разметка |
| --- | --- | --- |
| Малый | 17 профилей (`prisma/seed/employer` + `extra-profiles.ts`) × 8 демо-вакансий | `labels.json`, агент; критерий близок к формуле подбора |
| Расширенный | 247 профилей × 24 вакансии, `synthetic.ts`, seed 20261010 | из скрытой «истины» генератора (ниже) |

## Расширенный набор

Типы профилей (11): сильный с доказательствами и категорией; сильный без категории; сильный, всё со слов; сильный, категория без
утверждений; слабый, категория без утверждений; переоценивший себя; сильный в соседнем стеке; средний; слабый джун; две
специализации; без специализации. Вакансии: backend, frontend, engineering, ai; Junior, Middle, Senior; по 6–7 требований
из тематического окна каталога + стек.

**Скрытая истина.** У профиля есть латентное владение 0…1 по каждому утверждению каталога и латентный грейд. Подбор
видит только зашумлённый слепок: утверждения (часть умений не заявлена, часть заявлена без умения), уровни
доказанности, категорию из теста (верна в ~80 %), стек, текст. Релевантность 0/1/2 (`truthRelevance`):

- `mastery(навык) = clamp((владение − 0,3) / 0,5)`; `truthCov` = доля весов требований вакансии, взвешенная по `mastery`;
- латентный грейд на ступень ниже вакансии — `truthCov × 0,7`, на две — `× 0,4`;
- `truthCov ≥ 0,7` — 2; `≥ 0,45` — 1; иначе 0. Специализация, категория, ФСП и стек в разметке не участвуют.

Где правило всё равно близко к формуле: оба — взвешенное покрытие требований вакансии. Разница: разметка считает по тому,
что человек умеет (скрыто), формула — по тому, что заявлено, с весом доказанности; формула добавляет категорию, ФСП, стек.
Профили и вакансии строятся из одного каталога, поэтому текст у BM25 и утверждения у подбора опираются на одни слова.

## Методы и метрики

- `ours` — `rankCandidates` + `dropUncovered` (код кабинета); `baselineClaims` — «больше утверждений своей специализации выше»;
  `bm25` — Okapi BM25 (k1 = 1,2, b = 0,75, idf Lucene, токены обрезаны до 6 знаков) по тексту профиля против текста вакансии;
  `random` — среднее по 50 случайным порядкам на вакансию.
- P@5, P@10, nDCG@10 (градуированная 0/1/2), Recall@50, MRR — по вакансиям, затем среднее; интервал 95 % — бутстреп по
  вакансиям, 1000 повторов (seed). Разница `ours − BM25` — парный бутстреп.
- В `results.json` добавлены ключи `legacyExtended` и `extended`; `summary` и `rows` — прежняя форма. `extended.byArchetype` —
  для каждого типа профиля: доля релевантных пар в топ-10, занятые места в топ-5 и сколько из них нерелевантные.

Тест: `npx vitest run tests/unit/eval/matching.test.ts`.
