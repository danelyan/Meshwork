# Контракт: охранный шлюз вызовов LLM (Senior)

Node 20, TypeScript, без SDK моделей и без реального времени. Модели передаются снаружи (`src/model.ts`,
файл платформы – не меняйте), часы – функцией `now()` (миллисекунды). Шлюз стоит между продуктом и моделью:
персональные данные (ПДн) не уходят наружу, расход токенов ограничен на пользователя и период, ответы
кэшируются, при сбое основной модели запрос уходит на запасную.

## `src/guard.ts`

```ts
import type { Model } from './model';
export type PiiType = 'EMAIL' | 'PHONE' | 'CARD';
export interface AskRequest { userId: string; prompt: string }
export interface Answer { text: string; model: string; cached: boolean; tokens: number; masked: number }
export type GuardErrorCode = 'bad_request' | 'budget_exceeded' | 'model_rejected' | 'unavailable';
export class GuardError extends Error { readonly code: GuardErrorCode }
export interface Usage { used: number; limit: number; resetsAt: number }
export interface AuditEntry {
  userId: string; at: number;
  outcome: 'ok' | 'cached' | 'budget_exceeded' | 'model_rejected' | 'unavailable';
  model: string | null; tokens: number; pii: Partial<Record<PiiType, number>>;
}
export interface Guard { ask(req: AskRequest): Promise<Answer>; usage(userId: string): Usage; audit(): AuditEntry[] }
export function createGuard(options: {
  primary: Model; fallback?: Model; now: () => number;
  budget: { tokens: number; periodMs: number };
  maxTokens?: number;      // по умолчанию 256; передаётся модели как есть
  cacheTtlMs?: number;     // по умолчанию 300000
}): Guard;
```

`ask` читает `now()` ровно один раз, в начале; это время `t` используется для окна бюджета, кэша и аудита.

### Проверка запроса
`userId` или `prompt` пустые после `trim` – `GuardError('bad_request')`; модель не вызывается, запись в аудит не пишется.

### Маскирование ПДн
Порядок проходов: email, затем карты, затем телефоны. Каждое найденное значение заменяется плейсхолдером
`[EMAIL_n]`, `[CARD_n]`, `[PHONE_n]`; `n` – с 1, отдельно для каждого типа, в порядке первого появления в `prompt`.
Одно и то же значение – один плейсхолдер.
- **EMAIL**: `локальная@домен.зона` (латиница, цифры и `._%+-` слева; латиница, цифры, `.-` и зона из 2+ букв справа).
  Значение сравнивается без учёта регистра.
- **CARD**: 16 цифр, подряд или группами по 4 через один пробел или дефис, не граничащие с другими цифрами, и
  проходящие проверку Луна. Не прошло проверку – не карта, текст остаётся как есть.
- **PHONE**: российский номер: `+7` или `8`, затем 10 цифр; код может быть в скобках, между частями допустимы пробелы и дефисы
  (`+7 (999) 123-45-67`, `8 999 123 45 67`, `89991234567`). Не граничит с другими цифрами. Значения
  `+7…` и `8…` с теми же 10 цифрами – одно и то же значение.

Модели уходит `prompt` с плейсхолдерами **без каких-либо обёрток**: ни в одном вызове (основной и запасной) не должно быть
исходных значений. В `text` ответа каждый плейсхолдер, выданный для этого запроса, заменяется обратно на исходное значение
(при нескольких написаниях одного значения – на первое встреченное). Незнакомые плейсхолдеры остаются как есть. Подстановка
идёт за один проход: подставленное значение заново не разбирается.
`Answer.masked` – число выданных плейсхолдеров (разных значений).

### Кэш
- Ключ – **маскированный** `prompt` (общий для всех пользователей); хранится маскированный ответ модели. Каждый ответ из кэша
  восстанавливается заново по таблице плейсхолдеров *текущего* запроса: чужие ПДн из кэша не вытекают.
- Попадание: `cached: true`, `model` – имя модели, чей ответ лежит в кэше, `tokens: 0`, модель не вызывается, бюджет не списывается. Свежесть: `t - storedAt < cacheTtlMs`,
  `storedAt` – время `t` запроса, который получил ответ от модели.
- Одновременные запросы с одним ключом, пока первый в работе, делят один вызов модели и его исход, в том числе ошибку.
  Присоединившиеся получают `cached: true`, `tokens: 0`, бюджет им не списывается.
- Ошибки не кэшируются.
- Порядок проверок: запрос → маскирование → кэш и текущие вызовы → бюджет → модель. Исчерпанный бюджет не мешает получить
  ответ из кэша.

### Бюджет
- Окна фиксированные, по часам: `окно = floor(t / periodMs)`. Лимит `budget.tokens` – на пользователя в окне.
- `usage(userId)` (читает `now()` сам): `used` – токены пользователя в текущем окне, `limit = budget.tokens`,
  `resetsAt = (окно + 1) * periodMs`. Неизвестный пользователь – `used: 0`.
- Перед вызовом модели: оценка = `ceil(длина_маскированного_prompt / 4) + maxTokens`. Если `used + оценка > limit` –
  `GuardError('budget_exceeded')`, модель не вызывается. Повторной проверки перед запасной моделью нет.
- Списывается `tokens` из ответа той модели, что ответила, в окно запроса (по `t`). Ошибки модели токенов не списывают.
- `Answer.tokens` – списанные токены этого запроса.

### Модели и сбои
- Сначала `primary`, при сбое – `fallback` (если задана) с тем же `prompt` и `maxTokens`. `Answer.model` – `name` ответившей.
- `ModelError` с `timeout`, `rate_limit`, `server` (и любая иная ошибка модели) – переход к запасной; запасной нет или она
  тоже упала так – `GuardError('unavailable')`.
- `ModelError` с `bad_request` или `auth` у любой модели – сразу `GuardError('model_rejected')`, без перехода дальше.

### Аудит
`audit()` возвращает копию журнала: по одной записи на каждый завершённый `ask` (кроме `bad_request`):
`at = t`, `outcome` (`ok` – ответила модель, `cached` – кэш или присоединение, иначе код ошибки), `model` (ответившая
модель; для кэша – `null`; для ошибок – `null`), `tokens` (списанные), `pii` – число разных значений по типам (типы без
значений в объект не входят). В журнале нет ни исходных значений ПДн, ни текста `prompt` и ответа.

## `DESIGN.md` (в корне репозитория)
Разделы `## Решения`, `## Компромиссы`, `## Границы применимости` – в каждом не меньше 200 символов: почему кэш хранит
маскированный ответ и ключом берёт маскированный запрос, чем рискует маскирование (ложные срабатывания, ПДн в именах и
адресах, которые регулярки не ловят), почему окна бюджета фиксированные и что при этом можно обойти, как бы вы мерили
полноту маскирования и где этот шлюз перестанет справляться.
