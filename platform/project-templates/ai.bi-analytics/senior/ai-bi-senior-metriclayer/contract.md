# Контракт: слой метрик (ai.bi-analytics, senior)

Модуль `metric_layer.py` и файл `DESIGN.md` – в корне репозитория. Окружение: Python 3.12, `pandas` 2.3.3, `numpy` 2.3.3,
стандартная библиотека, `pytest`; сеть недоступна. Входные `DataFrame` и словарь определений не изменяются.

```python
class MetricLayer:
    def __init__(self, definitions: dict, tables: dict[str, pd.DataFrame]) -> None
    def query(self, metric: str, by=(), filters: dict | None = None) -> pd.DataFrame
    def reconcile(self, metric: str, by) -> dict

def find_duplicates(definitions: dict) -> list[list[str]]
def plan_vs_fact(layer: MetricLayer, plan: pd.DataFrame, metric: str, by=("month",), tolerance: float = 0.05) -> pd.DataFrame
```

## Определения

`definitions` – словарь `имя метрики → описание`. Описание базовой метрики:
`{"type": "sum" | "count" | "count_distinct", "table": <имя в tables>, "column": <колонка>, "time": <колонка даты, необязательно>,
"filter": {<колонка>: <значение или список значений>, ...}, необязательно}`. Для `count` колонка не нужна (число строк).
Описание отношения: `{"type": "ratio", "numerator": <метрика>, "denominator": <метрика>}`; метрики в отношении могут быть
любыми (в том числе другими отношениями) и из разных таблиц.

Проверки в `__init__` (`ValueError` с точным текстом; метрики обходятся в порядке словаря, сначала все базовые проверки каждой
метрики, затем ссылки отношений; для базовой метрики в порядке: тип, таблица, `column`, `time`, колонки `filter`):
`"bad type: <метрика>"` (тип не из списка, описание не словарь, у `sum`/`count_distinct` нет `column`);
`"unknown table: <таблица>"`; `"unknown column: <таблица>.<колонка>"`; `"unknown metric: <ссылка>"` (отношение ссылается
на неописанную метрику); `"cyclic definition: <метрика>"` (отношение зависит само от себя прямо или через другие;
в тексте – первая в порядке словаря метрика цикла).

## Измерения

Измерение – колонка таблицы метрики, а для метрики с `time` ещё и `month` (строка `YYYY-MM`; реальная колонка с именем
`month` приоритетнее). Значения измерений приводятся к строке; пропуск (`None`, `NaN`, `NaT`, нечитаемая дата) – строка `"(none)"`:
строки с пропуском не теряются. Для отношения измерение должно быть допустимо для всех базовых метрик, от которых оно зависит;
недопустимое → `ValueError("unknown dimension: <имя>")`.

## `query(metric, by=(), filters=None)`

Неизвестная метрика → `ValueError("unknown metric: <имя>")`. `by` – последовательность измерений (без повторов, иначе
`ValueError("bad by")`). `filters` – `{измерение: значение или список значений}`, сравнение по строковому значению
измерения (`"2026-01"`), несколько фильтров – «И».

Базовая метрика: к таблице применяется `filter` определения (равенство или вхождение в список по исходным значениям), затем
фильтры запроса, затем группировка по `by`. `sum` – сумма `pd.to_numeric(column, errors="coerce")` (пропуски пропускаются; пустая
группа – `0.0`); `count` – число строк; `count_distinct` – число различных непропущенных значений `column`.
**Отношение считается из агрегатов на том же срезе** (числитель и знаменатель по каждой группе), а не как среднее по строкам и
не как среднее отношений групп: группы объединяются полным соединением, отсутствующая сторона – `0`, знаменатель `0` → `NaN`.

Результат – `DataFrame` с колонками `*by, metric`; строки отсортированы по измерениям (как по строкам, слева направо), индекс
`0..n-1`. Без `by` – ровно одна строка (пустой срез даёт `0` / `0.0` / `NaN` для отношения). С `by` и пустым срезом –
пустой `DataFrame` с теми же колонками. Типы: `sum` – `float64` (округлено до 2 знаков), `count`/`count_distinct` – `int64`,
`ratio` – `float64` (округлено до 4 знаков).

## `reconcile(metric, by)`

Сверка среза с итогом. Возвращает словарь: `metric`, `total` (значение без `by`), `grouped_sum` (сумма значений по группам
`by`), `diff = total - grouped_sum`, `additive` (`True` для `sum` и `count`, иначе `False`), `consistent`. Для `sum` и `count`
сумма срезов обязана совпадать с итогом (`consistent = abs(diff) < 1e-9`, потеря строк с пропуском измерения – ошибка слоя);
для `count_distinct` значение `consistent` считается так же, но расхождение – не ошибка, а сигнал, что измерение не функция
сущности (один уникальный объект попал в несколько срезов), `additive = False`. Для отношения: `grouped_sum` и `diff` – `None`,
`additive = False`, `consistent = None`. Сверка идёт по неокруглённым значениям (иначе округление срезов дало бы ложное расхождение); в ответ `total` и `grouped_sum` округлены как в `query`, `diff` – до 4 знаков.

## `find_duplicates(definitions)`

Базовые метрики с одинаковой логикой (тип, таблица, колонка, `time`, `filter` с точностью до порядка ключей и порядка значений в
списках; для `count` колонка игнорируется) под разными именами. Результат – список групп (каждая – отсортированный список имён, длина ≥ 2),
группы отсортированы по первому имени. Отношения сравниваются по паре (числитель, знаменатель): совпавшая пара – тоже дубль.
Дубли не ошибка, а материал для управления определениями.

## `plan_vs_fact(layer, plan, metric, by=("month",), tolerance=0.05)`

`plan` – `DataFrame` с колонками измерений из `by` и `plan` (число). `by` непустой (иначе `ValueError("bad by")`);
нет колонки → `ValueError("missing column: <имя>")`; `tolerance` – число ≥ 0 (иначе `ValueError("bad tolerance")`); повтор ключа
в плане → `ValueError("duplicate plan key")`. Значения измерений в плане приводятся к строке. Факт – `layer.query(metric, by)`.

Результат – колонки `*by, fact, plan, delta, delta_pct, status`, полное соединение факта и плана по `by`, строки по измерениям,
индекс `0..n-1`. Нет факта в группе – `fact = 0.0`; нет плана – `plan = NaN`. `delta = fact - plan`, `delta_pct = delta / plan`
(`NaN`, если плана нет или он `0`). `fact`, `plan`, `delta` округлены до 2 знаков, `delta_pct` – до 4 (считается по неокруглённым).
`status`: `"no_plan"` – плана нет; `"no_fact"` – план есть, а факт `NaN` (отношение с нулевым знаменателем); план `0`: `"on_plan"` при факте `0`, иначе `"no_target"`; иначе `"over"` при
`delta_pct > tolerance`, `"under"` при `delta_pct < -tolerance`, иначе `"on_plan"` (граница допуска – «в плане»).

## `DESIGN.md`

Разделы `## Решения`, `## Компромиссы`, `## Границы применимости` – в каждом не меньше 200 символов: почему отношение считается из
агрегатов, а не как среднее отношений; что делать с пропущенными значениями измерений и почему их нельзя отбрасывать; почему
`count_distinct` не складывается по срезам и как это ловит сверка; кто и как владеет определением метрики (одно имя – одно определение,
дубли, изменение определения и история); как хранить и согласовывать план; что меняется при переносе слоя в SQL/хранилище на больших объёмах.

Видимые тесты – `tests/visible/` (`python -m pytest tests/visible`).
