# Контракт: реестр версий модели и пакетный инференс (ai.ml-engineering, Senior)

Python 3.12, стандартная библиотека (numpy допустим). Модуль `registry.py` в корне репозитория. Сервис держит
несколько версий обученной линейной модели, переключает активную и считает предсказания пачками. Состояние
хранится в памяти объекта, но выгружается в JSON-совместимый `dict`.

## Модель

```python
{"features": ["age", "income"], "weights": [0.03, -0.0001], "bias": -0.5, "threshold": 0.5}
```

`score = 1 / (1 + exp(-(bias + Σ weights[i] * x[features[i]])))`, `label = 1`, если `score >= threshold`, иначе `0`.
`threshold` необязателен (по умолчанию `0.5`). Сигмоида не должна падать с `OverflowError` на больших по модулю
аргументах (`z = ±1000` даёт `1.0` и `0.0`).

## API

```python
class ModelRegistry:
    def register(self, version: str, model: dict) -> None
    def activate(self, version: str, allow_schema_change: bool = False) -> None
    def rollback(self) -> str
    def active_version(self) -> str | None
    def versions(self) -> list[str]
    def get_model(self, version: str) -> dict
    def predict_batch(self, rows, version: str | None = None) -> dict
    def export_state(self) -> dict
    @classmethod
    def from_state(cls, state: dict) -> "ModelRegistry"
```

### `register`
- `version` – непустая строка. Модель проверяется: `features` – непустой список непустых уникальных строк;
  `weights` – список конечных чисел (`int`/`float`, не `bool`) той же длины; `bias` – конечное число;
  `threshold` (если есть) – число строго между 0 и 1. Иначе `ValueError`.
- Версии неизменяемы: повторная регистрация версии с **равной** моделью – без эффекта; с другой – `ValueError`.
- Реестр хранит копию: последующие правки переданного `dict` на реестр не влияют.
- `versions()` – версии в порядке регистрации. `get_model(version)` – копия модели (правка копии реестр не меняет);
  неизвестная версия – `KeyError`.

### `activate` и `rollback`
- `activate(v)`: неизвестная версия – `KeyError`. Первая активация проходит всегда. Дальше новая версия
  **совместима**, если множество её `features` равно множеству признаков текущей активной (порядок значения не имеет:
  веса привязаны к именам). Несовместимая активация – `ValueError`, активная версия не меняется;
  с `allow_schema_change=True` разрешена.
- Активация уже активной версии – без эффекта.
- `rollback()` возвращает на предыдущую активную версию (в порядке активаций, повторные откаты идут дальше вглубь
  истории) и возвращает её имя. Проверка совместимости при откате не выполняется. Если возвращаться некуда –
  `LookupError`, состояние не меняется. Откат не заносит версию в историю как новую активацию:
  после `activate(a)`, `activate(b)` первый `rollback()` вернёт `a`, второй – `LookupError`.
- `active_version()` – `None`, пока ничего не активировано.

### `predict_batch(rows, version=None)`
- `rows` – любая итерируемая коллекция словарей «признак → значение». `version=None` – активная версия;
  нет активной – `RuntimeError`; неизвестная явная версия – `KeyError`.
- **Версия фиксируется до чтения `rows`** и применяется ко всей пачке: если активная версия переключится, пока
  `rows` потребляется (например, генератором), пачка всё равно считается по зафиксированной.
- Ошибка в одной строке не роняет пачку. Возвращается

```python
{"version": "v1", "results": [{"index": 0, "ok": True, "score": 0.73, "label": 1},
                              {"index": 1, "ok": False, "error": "missing_feature:age"}, ...],
 "n_ok": 1, "n_failed": 1}
```
  `results` – по одному элементу на строку, в порядке входа. Коды ошибок: `not_a_dict` (строка не `dict`),
  `missing_feature:<имя>` (нет признака; берётся первый по порядку `features` модели), `bad_value:<имя>`
  (значение не число, `bool` или нечисловое, `nan`/`inf`; проверяется первый подходящий признак по порядку).
  Лишние ключи в строке игнорируются. Пустая `rows` – пустой `results`, нули в счётчиках.

### `export_state` / `from_state`
- `export_state()` – `dict`, сериализуемый `json.dumps`, содержит все версии, активную и историю активаций.
- `from_state(state)` восстанавливает реестр: те же версии (в том же порядке), активная версия и возможность `rollback()`.
  Состояние проверяется (модели – теми же правилами, активная и версии из истории должны существовать), иначе `ValueError`.
  Изменение `state` после вызова на реестр не влияет.

## `DESIGN.md` (в корне репозитория)
Разделы `## Решения`, `## Компромиссы`, `## Границы применимости` – в каждом не меньше 200 символов: почему версии
неизменяемы и версия фиксируется на пачку, что даёт проверка совместимости схемы и чего не ловит (дрейф распределения,
смена масштаба признака), как бы вы делали канареечный запуск и откат под нагрузкой, что сломается при нескольких
процессах с общим реестром.
