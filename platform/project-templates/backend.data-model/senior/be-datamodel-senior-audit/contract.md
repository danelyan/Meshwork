# Контракт: версионируемый каталог с аудитом (Senior)

Python 3.12, только стандартная библиотека (`sqlite3`). Модуль `registry.py` в корне репозитория.
Хранилище — SQLite; **схему вы проектируете сами** (имена таблиц не проверяются), проверяется только поведение
функций ниже. Деньги — целые копейки.

Задача: каталог позиций, в котором ничего не пропадает бесследно. Каждое изменение получает номер версии и запись
в журнал, удаление «мягкое», конкурирующие правки не затирают друг друга, а прошлое состояние можно восстановить.

## Запись

Позиция идентифицируется ключом `key` (непустая строка) и имеет поля `title` (непустая после `strip()` строка) и
`price_kop` (`int`, не `bool`, `>= 0`). Все функции возвращают запись как словарь:

```python
{"key": "pen", "title": "Pen", "price_kop": 100, "version": 1, "deleted": False}
```

`version` начинается с 1 и растёт ровно на 1 при каждом изменении, включая удаление и восстановление.

## Ошибки

```python
class DataError(Exception): ...
class DuplicateError(DataError): ...   # ключ уже занят (в том числе удалённой позицией)
class NotFoundError(DataError): ...    # нет такой позиции, она удалена, либо в запрошенный момент её не было
class ValidationError(DataError): ...  # некорректный аргумент
class ConflictError(DataError):        # expected_version не совпал с текущей версией
    current_version: int               # версия, которая реально хранится
```

Порядок проверок в каждой изменяющей функции: аргументы (`ValidationError`) → существование (`NotFoundError`) →
версия (`ConflictError`). Ни при какой ошибке не остаётся частичных изменений: ни состояния, ни записи журнала.

## Функции

`connect(path=":memory:", clock=None)` — открывает соединение и создаёт недостающее (`IF NOT EXISTS`); повторный
вызов на существующем файле данные не трогает. `clock` — функция без аргументов, возвращающая целое число
(момент времени); по умолчанию `lambda: int(time.time())`. Время нигде больше не читается, `clock` вызывается
не более одного раза на операцию. Соединение должно работать при нескольких подключениях к одному файлу из разных
потоков: ожидание блокировки — не меньше 10 секунд.

Все изменяющие функции принимают `actor` — непустую строку (кто сделал изменение).

- `create(conn, key, title, price_kop, actor)` → запись с `version` 1. Занятый ключ — `DuplicateError`.
- `update(conn, key, changes, expected_version, actor)` — `changes` — непустой словарь с ключами только
  `title` и/или `price_kop` (значения проверяются как выше; иное — `ValidationError`). Удалённая позиция —
  `NotFoundError`. Если после применения `changes` значения не отличаются от текущих — ничего не меняется:
  версия прежняя, в журнал ничего не пишется, возвращается текущая запись (версия при этом всё равно сверяется
  с `expected_version`). Иначе версия +1.
- `delete(conn, key, expected_version, actor)` — мягкое удаление: `deleted` становится `True`, версия +1.
  Удалённая позиция — `NotFoundError`.
- `restore(conn, key, expected_version, actor)` — снимает удаление, версия +1. Позиция не удалена — `ValidationError`.
- `revert(conn, key, to_version, expected_version, actor)` — возвращает **поля и признак удаления** позиции к
  тем, что были в версии `to_version`, как **новую** версию (+1; история не переписывается). Если состояние уже
  совпадает — как в `update`, без изменений. `to_version` — `int` от 1 до текущей версии, иначе `ValidationError`.
  Работает и для удалённой позиции.
- `get(conn, key, include_deleted=False)` → запись; удалённая без `include_deleted` — `NotFoundError`.
- `list_active(conn)` → записи неудалённых позиций, по возрастанию `key`.
- `history(conn, key)` → журнал позиции по возрастанию `version`, включая удалённую (нет позиции — `NotFoundError`).
  Элемент:

  ```python
  {"version": 2, "op": "update", "actor": "ann", "at": 1700000005,
   "changes": {"price_kop": [100, 120]}}
  ```

  `op` — `create` / `update` / `delete` / `restore` / `revert`. `at` — значение `clock()` в момент операции.
  `changes` — только реально изменившиеся поля `title` и `price_kop` в виде `[было, стало]`; для `create`
  было — `None`; для `delete` и `restore` — `{}`; для `revert` — изменившиеся поля (может быть `{}`, если
  менялся только признак удаления). Журнал неизменяем: поздние правки не меняют уже записанные элементы.
- `as_of(conn, key, at)` → запись **в том виде, каким она была на момент `at`** (включительно): берётся последняя
  версия с `at_версии <= at` (при равных `at` — с большим номером). Если на этот момент позиции ещё не было или
  она была удалена — `NotFoundError`. `at` — `int`, иначе `ValidationError`.
- `snapshot(conn, at)` → записи всех позиций, существовавших и не удалённых на момент `at`, по возрастанию `key`;
  у каждой `version` и поля — как на тот момент.

## Конкурентность

Несколько потоков со своими соединениями к одному файлу вызывают изменяющие функции одновременно. Для набора
запросов с одинаковым `expected_version` по одной позиции ровно один завершается успехом, остальные —
`ConflictError`; никто не падает с `sqlite3.OperationalError` («database is locked») и не оставляет дыр или
дублей в нумерации версий. Одновременное `create` одного ключа: один успех, остальные — `DuplicateError`.
