# Контракт: объединение запросов к источнику (Middle)

Node 20, TypeScript, Express 5. Источник данных – медленный и платный по числу обращений; сервис
должен обращаться к нему как можно реже, не теряя ни одного ответа. Своих таймеров не заводить
(`setTimeout`/`setInterval`): порядок событий определяют только промисы и микрозадачи.

## `src/singleflight.ts`

```ts
export interface Singleflight {
  do<T>(key: string, fn: () => Promise<T>): Promise<T>;
  inFlight(): number;
}
export function createSingleflight(): Singleflight;
```

- Первый `do(key, fn)` для свободного ключа вызывает `fn` (сразу, синхронно) и возвращает его результат.
- Пока `fn` не завершилась, любой `do` с тем же `key` **не вызывает свою `fn`**, а получает результат первой.
  Все ожидающие получают то же значение; при отказе – тот же отказ (та же причина).
- Завершение (успех или отказ) освобождает ключ: следующий `do` снова вызывает `fn`. Отказ не запоминается.
- `fn` бросила исключение синхронно – `do` возвращает отклонённый промис, ключ освобождается.
- Разные ключи независимы. `inFlight()` – число ключей, по которым `fn` ещё выполняется.

## `src/batcher.ts`

```ts
export class KeyNotFoundError extends Error { readonly key: string }   // name === 'KeyNotFoundError'
export interface BatcherOptions<V> {
  fetchMany: (keys: string[]) => Promise<Map<string, V>>;
  maxBatchSize: number;
  maxConcurrency: number;
}
export interface Batcher<V> { load(key: string): Promise<V> }
export function createBatcher<V>(options: BatcherOptions<V>): Batcher<V>;
```

- `maxBatchSize` и `maxConcurrency` – целые ≥ 1, иначе `RangeError`.
- Вызовы `load`, сделанные подряд синхронно (без `await` между ними), собираются вместе и уходят в источник
  одной или несколькими пачками. Пачка – не больше `maxBatchSize` ключей, ключи в порядке первого запроса.
- Один ключ в `fetchMany` передаётся не больше одного раза за раз: повторный `load` ключа, который уже
  ждёт отправки **или уже запрошен и не завершён**, присоединяется к нему и получает тот же результат.
  После завершения ключ свободен – результаты не кешируются, следующий `load` снова обращается к источнику.
- Одновременно выполняется не больше `maxConcurrency` вызовов `fetchMany`; остальные пачки ждут в порядке
  создания и стартуют по мере освобождения слотов.
- Ключ есть в `Map` – его ожидающие получают значение. Ключа нет – они получают отказ `KeyNotFoundError`
  (с `key`); остальные ключи пачки это не затрагивает.
- `fetchMany` отклонилась или бросила исключение – **все** ожидающие ключей этой пачки получают эту же ошибку.
  Другие пачки не затрагиваются, слот освобождается, пачка не повторяется автоматически.

## `src/app.ts`

```ts
export function createApp(deps: { batcher: Batcher<Item> }): Express;   // Item = { id: string; name: string }
```

- `GET /items/:id` – `200` с `Item`; `KeyNotFoundError` → `404 { "error": "not_found" }`;
  любая другая ошибка источника → `502 { "error": "upstream_failed" }`.
- `GET /items?ids=a,b,c` – идентификаторы через запятую; повторы убираются (первое вхождение), пустые
  элементы игнорируются; пустой или отсутствующий `ids` – `400 { "error": "ids_required" }`.
  Ответ `200 { "items": Item[], "missing": string[] }`: найденные в порядке запроса, ненайденные – в `missing`.
  Любая другая ошибка источника по любому из ключей – `502 { "error": "upstream_failed" }` для всего запроса.
- Все чтения идут через `batcher.load`. Ключи одного запроса `GET /items?ids=…` передаются батчеру синхронно,
  до ожидания каких-либо результатов, – иначе они не попадут в общие пачки.
