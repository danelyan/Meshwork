# Лимитер запросов: проектные решения

## Решения
Token bucket на ключ: позволяет короткие всплески до ёмкости и задаёт среднюю скорость пополнением.
Пополнение считается лениво при обращении – нет таймеров и фоновых задач. Время – только из now(),
поэтому поведение воспроизводимо в тестах. LRU через порядок вставки Map даёт O(1) на вытеснение.

## Компромиссы
Вытеснение неполного ведра «прощает» клиенту израсходованные токены: при атаке множеством ключей можно
выбить ведро активного клиента и получить лишний всплеск. Альтернатива – отказывать новым ключам при
переполнении, но тогда легитимные новые клиенты получат 429. Выбрано вытеснение ради доступности.

## Границы применимости
Состояние в памяти одного процесса: при нескольких экземплярах лимит умножается на число экземпляров.
Для кластера нужен общий стор (Redis с атомарным скриптом) или шардирование ключей по экземплярам;
это добавляет сетевую задержку и точку отказа – при недоступности стора выбирать fail-open или fail-closed.
