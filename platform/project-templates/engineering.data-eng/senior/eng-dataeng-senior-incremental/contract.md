# Контракт: инкрементальная агрегация платежей — дедупликация, поздние события, водяной знак (Senior)

Python 3.12, только стандартная библиотека. Модуль `pipeline.py` в корне репозитория. События приходят
пачками (микробатчи) из очереди «как минимум один раз»: бывают повторы, опоздания и мусор. Состояние между
пачками — обычный `dict`, который вызывающий код хранит сам (например, в JSON-файле).

## Событие

```json
{"event_id": "e-1", "user_id": "u-1", "kind": "purchase", "amount_kop": 19900, "event_time": "2026-10-01T10:00:00+03:00"}
```

## Функции

```python
def process_batch(state: dict | None, events: list[dict], allowed_lateness: timedelta = timedelta(hours=2)) -> dict
def report(state: dict) -> dict
def seen_count(state: dict) -> int
```

### `process_batch`
- `state=None` — начальное состояние. Функция **не меняет** переданный `state` и возвращает новый;
  состояние сериализуется `json.dumps` без доп. параметров.
- **Проверка.** Событие не по схеме не агрегируется и попадает в отбраковку с причиной (первая подходящая
  по порядку): `missing_field` (нет любого из пяти полей), `bad_type` (`event_id`/`user_id` не непустые
  строки), `bad_kind` (не `purchase`/`refund`), `bad_amount` (`amount_kop` не целое ≥ 0; `bool` — не целое),
  `bad_time` (`event_time` не ISO 8601 или без часового пояса).
- **Дедупликация.** Повтор `event_id`, уже учтённого в этой или прошлых пачках, не учитывается и считается в `duplicates`.
- **Водяной знак.** `watermark` = максимальное `event_time` среди учтённых событий **прошлых пачек** минус
  `allowed_lateness`. Событие с `event_time < watermark` — позднее: не агрегируется, считается в `late`.
  Внутри пачки водяной знак не меняется, поэтому результат не зависит от порядка событий в пачке.
  Порядок проверок: схема → позднее (даже если id уже встречался) → повтор.
- **Память.** Помнить id нужно только для событий не старше водяного знака: событие старше него и так
  будет поздним. `seen_count(state)` — сколько id хранится; после продвижения водяного знака оно уменьшается.
- **Агрегаты** — по дню UTC `event_time` и `user_id`: суммы покупок и возвратов в копейках, `net_kop`
  (покупки минус возвраты) и число событий.

### `report(state)`

```python
{
  "days": [{"date": "2026-10-01", "user_id": "u-1", "purchases_kop": 0, "refunds_kop": 0, "net_kop": 0, "events": 0}, ...],
  "late": 0, "duplicates": 0,
  "rejected": {"bad_time": 1, ...},      # только встретившиеся причины
  "watermark": "2026-10-01T08:00:00+00:00" | None  # в UTC, isoformat()
}
```
`days` отсортированы по `(date, user_id)`. Повторная обработка той же пачки не меняет `days` и `watermark`
(растут только счётчики `duplicates`, `late`, `rejected`).
