# Контракт: исполнитель CI-пайплайна (engineering.devops, middle)

Модуль `ciexec.py` в корне репозитория. Python 3.12, только стандартная библиотека, без сети, без потоков и
реального времени: исполнение шагов и время **моделируются** (см. «Виртуальное время»).

```python
class PipelineError(ValueError):
    code: str       # "invalid_pipeline" | "duplicate_id" | "unknown_dependency" | "cycle"
    details: list   # см. ниже

def plan(pipeline: dict) -> list[str]
def run(pipeline: dict, executor, files: dict | None = None, cache: dict | None = None, max_parallel: int = 1) -> dict
```

## Пайплайн

```json
{"steps": [
  {"id": "lint",  "run": "make lint"},
  {"id": "build", "run": "make build", "needs": ["lint"], "inputs": ["src/app.c"]},
  {"id": "test",  "run": "make test",  "needs": ["build"], "retries": 2, "cache": false}
]}
```

Поля шага: `id` (непустая строка), `run` (строка), `needs` (список id, по умолчанию пустой), `inputs` (список путей
файлов-входов, по умолчанию пустой), `retries` (целое ≥ 0, по умолчанию 0), `cache` (bool, по умолчанию `true`).

## `plan(pipeline)` — порядок исполнения

Возвращает список id в топологическом порядке (зависимости раньше зависимых). Порядок детерминирован: из всех
шагов, готовых к запуску, берётся тот, что раньше объявлен в `steps`. Ошибки — `PipelineError` с `code`:

| `code` | Когда | `details` |
| --- | --- | --- |
| `invalid_pipeline` | нет списка `steps`, шаг не объект, нет `id`/`run` нужного типа, неверные `needs`/`inputs`/`retries`/`cache` | `[]` |
| `duplicate_id` | повторяющийся `id` | `[повторяющиеся id по возрастанию]` |
| `unknown_dependency` | `needs` ссылается на несуществующий шаг | `[[id шага, id отсутствующей зависимости], ...]` по возрастанию |
| `cycle` | есть цикл (в том числе шаг зависит сам от себя) | id шагов, которые не удалось упорядочить (в цикле или зависящие от цикла), по возрастанию |

Проверки идут в порядке строк таблицы; `run` валидирует так же и бросает те же ошибки до первого вызова executor.

## `run(...)`

`max_parallel` — целое ≥ 1, иначе `ValueError`. `files` — словарь `путь → содержимое (str)`; `cache` — словарь
(по умолчанию новый пустой), который `run` изменяет.

### Виртуальное время и executor

Время начинается с 0. `executor(step: dict, attempt: int) -> {"ok": bool, "duration": число >= 0}` вызывается
с исходным словарём шага и номером попытки с 1. Исключение executor — неуспешная попытка с `duration` 0.
Шаг делает попытки подряд, пока одна не успешна или не исчерпаны `retries + 1` попыток; его время работы — сумма
`duration` всех попыток. Все попытки шага вызываются в момент его старта.

### Планировщик

Одновременно выполняется не больше `max_parallel` шагов. Шаг готов, когда все его зависимости завершились
успешно (`success` или `cached`). Свободные слоты заполняются готовыми шагами в порядке `plan()` в тот же момент
времени, когда слот освободился. Если несколько шагов завершаются в один момент, они обрабатываются в порядке `plan()`.
Шаг из кеша занимает 0 времени и слот не занимает.

### Кеш

Ключ шага (SHA-256 в hex от `json.dumps([id, run, [[путь, sha256(содержимое) | null], ...по возрастанию пути],
[[id зависимости, ключ зависимости], ...по возрастанию id]], separators=(",", ":"))`, `null` — файла нет в `files`).
Поэтому изменение входа или команды меняет ключ шага и всех зависимых. Шаг с `cache: true` и ключом, который есть
в `cache`, не запускается: статус `cached`, executor не вызывается. Успешный шаг (в том числе с `cache: false`)
для `cache: true` записывается: `cache[ключ] = {"step": id}`. Неуспешные шаги в кеш не попадают.
У шага с `cache: false` ключ всё равно считается (его используют зависимые).

### Падения

Шаг, у которого все попытки неуспешны, — `failed`. Все его прямые и косвенные зависимые — `skipped`
(executor не вызывается), независимые шаги продолжают работу.

### Результат

```python
{
  "ok": bool,                    # нет failed-шагов
  "makespan": число,             # максимум end среди не пропущенных шагов, иначе 0
  "order": ["id", ...],          # id в порядке старта (cached и failed тоже; skipped нет)
  "counts": {"success": 0, "cached": 0, "failed": 0, "skipped": 0},
  "steps": {"<id>": {"status": "success|cached|failed|skipped", "start": число|None, "end": число|None,
                      "attempts": int, "cache_key": str|None}}
}
```

`attempts` — число вызовов executor (0 для `cached` и `skipped`). `end = start + сумма duration`. `cache_key` — ключ
для `success`, `cached` и `failed`, `None` для `skipped`. Порядок ключей в `steps` не важен.
