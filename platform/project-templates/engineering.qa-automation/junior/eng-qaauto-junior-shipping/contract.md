# Контракт: тест-дизайн для расчёта стоимости доставки (engineering.qa-automation, junior)

Задача QA: по спецификации функции расчёта доставки написать **таблицу проверок**, которая отличает
правильную реализацию от неправильных. Саму функцию писать не нужно — платформа подставит свои реализации.

## Что сдать

Модуль `src/cases.ts` (ES-модуль) экспортирует `cases: Case[]`. Типы — в `src/types.ts` (менять не нужно).

```ts
interface Case {
  name: string;          // уникальное непустое имя кейса
  input: Order;          // вход функции
  expected?: number;     // ожидаемая стоимость ...
  throws?: ErrorCode;    // ... либо ожидаемая ошибка: у Error сообщение равно коду
}                        // ровно одно из expected / throws
```

Платформа вызывает `shippingCost(case.input)` для каждого кейса и сравнивает результат строго (`===`) с `expected`
либо проверяет, что брошена `Error` с `message === throws`. Свои реализации и код вызова писать не нужно:
ожидаемые значения вы выводите из спецификации ниже, а не из чьего-то кода.

## Спецификация функции `shippingCost(order): number`

`Order`: `{ weightKg: number, zone: 'city' | 'region' | 'country', express: boolean, subtotal: number }`.
`subtotal` — сумма заказа в той же валюте, что и результат; результат — целое число.

1. Базовая цена по весу: до 1 кг включительно — 300; свыше 1 до 5 кг включительно — 500; свыше 5 до 20 кг включительно — 900.
2. Зона умножает базовую цену: `city` ×1, `region` ×1.5, `country` ×2.5.
3. `express: true` добавляет 40 % к цене после применения зоны. В зону `country` экспресс недоступен.
4. Бесплатная доставка: если `express` ложно и `subtotal >= 5000`, результат 0. На экспресс скидка не распространяется.
5. Ошибки (`throws`), в порядке проверки:
   `invalid_weight` — вес не конечное число или `<= 0`;
   `too_heavy` — вес больше 20 кг;
   `invalid_subtotal` — сумма не конечное число или меньше 0;
   `invalid_zone` — зона не из списка;
   `express_unavailable` — экспресс в зону `country`.
   Ошибка проверяется раньше бесплатной доставки.

## Как оценивается

- Таблица корректной формы: имена уникальны и непусты, у каждого кейса ровно одно из `expected` / `throws`;
  кейсов не меньше 12.
- Правильная реализация проходит **каждый** ваш кейс. Кейс с неверным ожиданием делает таблицу негодной —
  мутанты в этом случае не засчитываются.
- Для каждой из набора заведомо сломанных реализаций (мутантов: сдвинутая граница, пропущенная проверка,
  неверный коэффициент, не та база для надбавки и т. п.) хотя бы один ваш кейс должен упасть. Чем больше
  мутантов поймано, тем выше балл. Видимые тесты показывают эталон и два мутанта из набора.
- Независимая реализация с тем же поведением тоже проходит все кейсы (не завязывайте ожидания на детали одной реализации).

## Окружение проверки

Node.js 20, TypeScript без проверки типов (vitest), сети нет, свои зависимости не устанавливаются.
Не импортируйте в `src/cases.ts` ничего, кроме `./types`.
