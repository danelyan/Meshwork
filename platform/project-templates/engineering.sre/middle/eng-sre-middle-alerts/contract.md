# Контракт: движок алертов по burn rate (engineering.sre, middle)

Модуль `alerts.py` в корне репозитория. Окружение: Python 3.12, только стандартная библиотека, без сети и потоков.
Время приходит только через инъецированную функцию `now()` (секунды, число). Проверка — pytest.

```python
class AlertEngine:
    def __init__(self, rules: list[dict], now, notify) -> None
    def record(self, service: str, ok: bool) -> None
    def evaluate(self) -> None
    def state(self, alertname: str, service: str) -> str
    def alerts(self) -> list[dict]
    def add_silence(self, matchers: dict, duration_s: float) -> str
    def remove_silence(self, silence_id: str) -> bool
```

`now` — вызываемый без аргументов, возвращает текущее время. `notify(event: dict)` — приёмник уведомлений.

## Правила

```python
{
  "name": str,                 # уникальное имя алерта
  "slo": float,                # цель, строго между 0 и 1
  "windows": [{"long_s": N, "short_s": M, "burn": B}, ...],   # непустой список
  "for_s": 0,                  # сколько условие должно держаться до firing
  "keep_firing_for_s": 0,      # сколько условие должно быть ложным до resolved
  "repeat_interval_s": 3600,   # повтор уведомления firing
  "labels": {}                 # статические метки, строки
}
```

Обязательны `name`, `slo`, `windows`; остальное — значения по умолчанию из примера. Нарушение (пустое или повторяющееся
имя, `slo` вне (0, 1), пустой список окон, не выполнено `0 < short_s < long_s`, `burn <= 0`, `for_s` или
`keep_firing_for_s` меньше 0, `repeat_interval_s <= 0`, нет обязательного поля) → `ValueError` из конструктора.
Правила и список окон внутри конструктор копирует: изменение исходных объектов позже на движок не влияет.

## События и условие

`record(service, ok)` запоминает результат запроса сервиса с отметкой `now()`. Сервис «известен» движку после первого
`record`. Алерт — это пара (правило, сервис); метки алерта: метки правила плюс `alertname` (имя правила) и `service`.

`burn(окно)` для пары на момент `t` — `error_ratio / (1 - slo)`, округлённое `round(..., 9)`, где `error_ratio` —
доля `ok=False` среди событий с `t - окно < ts <= t`; нет событий в окне → `0`.
Условие вычисляется заново на каждый `evaluate()` по текущему `t`: ошибки, вышедшие из окна, на него не влияют, и если в
`short_s` последних секунд нет новых ошибок, условие ложно (даже если в длинном окне ещё горит).
Условие истинно, если для **хотя бы одного** элемента `windows` верно **и** `burn(long_s) >= burn`, **и**
`burn(short_s) >= burn` (multi-window multi-burn-rate).

## Состояния

`evaluate()` берёт `t = now()` один раз и для каждой пары (правило × известный сервис) обновляет состояние:
`inactive` (по умолчанию, пары нет) → `pending` → `firing` → `resolved`.

- `inactive` или `resolved` и условие истинно: `for_s == 0` → сразу `firing`, иначе `pending` (отметка `since = t`).
- `pending`: условие ложно → `inactive`, без уведомлений; истинно и `t - since >= for_s` → `firing` (`since = t`).
- `firing`: условие истинно → остаётся (счётчик «условие ложно» сбрасывается). Ложно → запоминается момент, с которого оно
  ложно (первый такой `evaluate`); когда `t - этот момент >= keep_firing_for_s` → `resolved` (`since = t`).
  При `keep_firing_for_s == 0` это тот же `evaluate`.
- `resolved` остаётся до тех пор, пока условие снова не станет истинным (тогда — как для `inactive`).

`state(alertname, service)` возвращает строку состояния; неизвестная пара → `"inactive"`.
`alerts()` — список словарей `{"alertname", "service", "labels", "state", "since", "silenced"}` для пар в `pending` и
`firing`, отсортированный по `(alertname, service)`; `silenced` — попадает ли алерт под активное молчание в момент вызова.
`since` — время входа в текущее состояние.

## Уведомления

`notify` получает `{"type": "firing" | "resolved", "alertname", "labels", "at": t}` (`labels` — копия).

- **firing.** Пока алерт в `firing` и не под молчанием: если уведомление ещё не доставлено — отправить в этом `evaluate`;
  если доставлено, повторять не чаще, чем раз в `repeat_interval_s` (от времени последней доставки). Одно и то же
  состояние `firing` не порождает дублей между повторами.
- **Сбой доставки.** `notify` бросил исключение → `evaluate` его не пробрасывает, доставка не засчитывается и
  повторяется на следующем `evaluate`.
- **resolved.** Уведомление отправляется, только если для этого `firing` было доставлено хотя бы одно `firing`-уведомление.
  Под молчанием оно не отправляется и позже не досылается. Сбой доставки повторяется на следующем `evaluate`, пока алерт
  остаётся `resolved`; если алерт тем временем вновь стал `pending`/`firing`, недоставленное `resolved` отбрасывается.
- Новый `firing` после `resolved` — новый инцидент: `firing`-уведомление уходит заново, не дожидаясь `repeat_interval_s`.
- Переходы состояний от молчаний не зависят: молчание глушит только уведомления.

## Молчания

`add_silence(matchers, duration_s)` создаёт молчание на `[now(), now() + duration_s)` и возвращает его id (непустая строка,
уникальная). Молчание действует на алерт, если **все** пары `ключ: значение` из `matchers` совпадают с метками алерта
(точное равенство; нет такой метки — не совпало). Пустой `matchers` или `duration_s <= 0` → `ValueError`.
Если подходит хотя бы одно из нескольких молчаний — алерт заглушён. Алерт, который был под молчанием, а к его концу всё ещё `firing` и
недоставлен, получает уведомление на первом `evaluate` после окончания молчания.
`remove_silence(id)` → `True`, если молчание было, иначе `False`.

## Память

События старше самого длинного `long_s` среди правил можно отбрасывать: движок не должен копить журнал бесконечно (поведение не меняется).
