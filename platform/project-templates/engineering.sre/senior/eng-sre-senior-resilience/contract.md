# Контракт: клиент к нестабильной зависимости – circuit breaker, ретраи с бюджетом, load shedding (engineering.sre, senior)

Модуль `resilience.py` в корне репозитория. Окружение: Python 3.12, только стандартная библиотека, без сети и потоков.
Время приходит только через инъецированные `now()` (секунды, число) и `sleep(s)`; реальных часов и пауз нет.
Вызовы последовательные (один за другим). Проверка – pytest. Ещё нужен `DESIGN.md` – см. конец.

```python
class TransientError(Exception): ...
class Rejected(Exception):
    reason: str          # "shed" | "breaker_open"

class ResilientClient:
    def __init__(self, upstream, now, sleep, **config) -> None
    def call(self, request, priority: str = "normal")
    def state(self) -> str           # "closed" | "open" | "half_open"
    def stats(self) -> dict
```

`upstream(request)` – вызываемая зависимость: возвращает результат или бросает исключение. `TransientError` – временный
сбой (его повторяем и он считается ошибкой для breaker); любое другое исключение – окончательный ответ зависимости
(например, «неверный запрос»): `call` пробрасывает его сразу, без повторов, а для breaker оно считается **успехом**.
`call` возвращает результат `upstream`.

## Конфигурация (именованные аргументы, значения по умолчанию)

| имя | по умолчанию | смысл |
|---|---|---|
| `failure_threshold` | 5 | число ошибок в окне, открывающее breaker |
| `failure_window_s` | 10 | окно подсчёта ошибок |
| `cooldown_s` | 30 | сколько breaker остаётся открытым |
| `half_open_successes` | 2 | подряд успешных вызовов в `half_open`, чтобы закрыть |
| `max_attempts` | 3 | всего попыток на один `call` (первая + повторы), ≥ 1 |
| `backoff_s` | 0.1 | пауза перед повтором №1; перед повтором №k – `min(backoff_s * 2**(k-1), max_backoff_s)` |
| `max_backoff_s` | 2 | потолок паузы |
| `retry_ratio` | 0.2 | доля повторов от числа принятых вызовов в окне бюджета |
| `retry_min` | 1 | сколько повторов разрешено «в запас» сверх доли |
| `budget_window_s` | 10 | окно бюджета повторов |
| `capacity` | 100 | сколько вызовов принимается за `shed_window_s` |
| `shed_window_s` | 1 | окно приёма |

Неположительные `failure_threshold`, `failure_window_s`, `cooldown_s`, `half_open_successes`, `max_attempts`, `backoff_s`,
`max_backoff_s`, `budget_window_s`, `capacity`, `shed_window_s`, отрицательные `retry_ratio` и `retry_min`, неизвестное имя
конфигурации → `ValueError` из конструктора. `retry_ratio` и `retry_min` могут быть 0.

Во всех окнах «за последние `w` секунд» значит `t - w < ts <= t`.

## Порядок обработки `call(request, priority)`

Неизвестный `priority` (допустимы `"critical"`, `"normal"`, `"low"`) → `ValueError`, ничего не учитывается (даже в `stats`).
Дальше `stats()["calls"]` растёт на 1, и проверки идут строго в этом порядке:

1. **Breaker.** Если открыт (см. ниже) → `Rejected("breaker_open")`, `short_circuited` +1.
2. **Приём (load shedding).** Число принятых вызовов за последние `shed_window_s` секунд сравнивается с лимитом приоритета:
   `critical` – `capacity`, `normal` – `floor(capacity * 0.8)`, `low` – `floor(capacity * 0.5)`. Если число уже **не меньше**
   лимита → `Rejected("shed")`, `shed` +1; отклонённый вызов приёмный счётчик не увеличивает. Иначе вызов принят: в
   счётчик принятых добавляется отметка `now()`. Повторы принятые вызовы не увеличивают.
3. **Попытка.** Вызывается `upstream(request)`, `upstream_calls` +1, результат учитывается в breaker (ниже).
   Успех → вернуть результат. Не-`TransientError` → пробросить. `TransientError` →
4. **Решение о повторе.** По порядку: если это была последняя из `max_attempts` попыток → пробросить эту ошибку;
   если breaker сейчас открыт → `Rejected("breaker_open")` (`short_circuited` +1); если бюджет повторов исчерпан →
   пробросить эту ошибку (`retries_denied` +1). Иначе: отметка повтора добавляется в бюджет, `retries` +1, вызывается
   `sleep(пауза)` и сразу пункт 3: пункты 1 и 2 для повтора не выполняются (breaker проверен выше, приём повтор не считает).

**Бюджет повторов.** Повтор разрешён, если число повторов за последние `budget_window_s` секунд строго меньше
`floor(retry_ratio * N) + retry_min`, где `N` – число принятых вызовов за те же `budget_window_s` секунд (включая текущий).
Окно считается от `now()` в момент решения (до паузы).

## Circuit breaker

Состояния. Время открытия `opened_at`.
- `closed`: ошибкой считается каждая попытка с `TransientError`; ошибки хранятся с отметкой `now()` в момент результата.
  Когда число ошибок за последние `failure_window_s` секунд станет `>= failure_threshold` → `open`, `opened_at = now()`,
  список ошибок очищается. Успехи счётчик ошибок не сбрасывают.
- `open`: открыт, пока `now() < opened_at + cooldown_s`. Когда это время пришло – следующий `call` (и `state()`)
  считает breaker `half_open`.
- `half_open`: вызовы проходят. Каждый успех (в том числе не-`TransientError`) увеличивает счётчик подряд идущих
  успехов; когда он достиг `half_open_successes` → `closed` (список ошибок пуст). Любая ошибка (`TransientError`) →
  снова `open` с `opened_at = now()`, счётчик успехов обнуляется.

`state()` отражает состояние на момент вызова: открытый breaker после `cooldown_s` отдаёт `"half_open"`.
В `closed` и `half_open` пункт 1 проходит.

## `stats()`

Словарь `{"calls", "shed", "short_circuited", "upstream_calls", "retries", "retries_denied"}` – целые счётчики с начала жизни
клиента; возвращается копия.

## `DESIGN.md` (в корне репозитория)

Разделы `## Решения`, `## Компромиссы`, `## Границы применимости` – в каждом не меньше 200 символов: почему breaker, ретраи
и приём сложены именно в таком порядке и зачем бюджет повторов (что бывает при ретраях без бюджета на зависимость,
которая уже перегружена); почему приоритеты режут не поровну; что потеряет шаблон при параллельных вызовах и потоках
(состояние без блокировок), как бы это выглядело в Envoy/Istio, resilience4j или Polly; чем плох `sleep` без джиттера
при тысячах клиентов.
