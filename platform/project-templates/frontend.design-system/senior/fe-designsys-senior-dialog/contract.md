# Контракт: модальный Dialog (frontend.design-system, senior)

React 19, TypeScript, без сторонних библиотек. Проверка – Testing Library в jsdom: роли, атрибуты ARIA, `document.activeElement`
и клавиатурные события (`fireEvent.keyDown`). В jsdom событие `Tab` само фокус не двигает, поэтому ловушку фокуса нужно
делать явно: обработчиком `keydown`, который вызывает `preventDefault()` и `focus()`. Один модуль: `src/Dialog.tsx`;
в корне репозитория – `DESIGN.md`.

## API (compound)

```ts
export function Dialog(props: {
  open?: boolean;                       // задан – контролируемый режим
  defaultOpen?: boolean;                // начальное состояние неконтролируемого режима, по умолчанию false
  onOpenChange?: (open: boolean) => void;
  children?: React.ReactNode;
}): JSX.Element;
Dialog.Trigger: (props: ButtonHTMLAttributes) => JSX.Element;
Dialog.Content: (props: HTMLAttributes<HTMLDivElement> & { role?: 'dialog' | 'alertdialog' }) => JSX.Element | null;
Dialog.Title: (props: HTMLAttributes<HTMLHeadingElement>) => JSX.Element;
Dialog.Description: (props: HTMLAttributes<HTMLParagraphElement>) => JSX.Element;
Dialog.Close: (props: ButtonHTMLAttributes) => JSX.Element;
```

Остальные пропсы частей передаются на их элемент, собственные атрибуты контракта их перекрывают. Часть, использованная вне
`<Dialog>`, бросает `Error` с текстом `Dialog.<Часть> must be used within <Dialog>` (например, `Dialog.Trigger must be used within <Dialog>`).
`onOpenChange(next)` вызывается при каждой просьбе изменить состояние; в контролируемом режиме состояние меняется только
через проп `open`, в неконтролируемом – сразу.

## Разметка

- `Trigger` – `<button type="button">` с `aria-haspopup="dialog"`, `aria-expanded` (`"true"` / `"false"`) и `aria-controls` =
  id окна, только пока оно открыто. Клик просит открыть окно (`onOpenChange(true)`); если у кнопки есть свой `onClick` и он
  вызвал `preventDefault()`, окно не открывается.
- `Content` при закрытом окне ничего не рендерит. Открытое окно рендерится в `document.body` (портал) как два вложенных
  элемента: внешний `<div data-dialog-overlay>` и внутренний `<div role="dialog">` (или `alertdialog`, если задан `role`)
  с `aria-modal="true"`, уникальным `id` и `tabIndex={-1}`.
- `aria-labelledby` = id `Title`, `aria-describedby` = id `Description` – только пока соответствующая часть смонтирована
  внутри `Content`; иначе атрибута нет. `Title` – `<h2>`, `Description` – `<p>`, `Close` – `<button type="button">`,
  клик по нему просит закрыть окно (`onOpenChange(false)`). Идентификаторы разных окон на странице не пересекаются.

## Фокус

- При открытии фокус переходит внутрь окна: на первый элемент с атрибутом `data-autofocus`, иначе на первый
  табулируемый элемент, иначе на сам `role="dialog"`.
- Табулируемый элемент (в порядке DOM): `a[href]`, `button`, `input` (кроме `type="hidden"`), `select`, `textarea` и любой
  элемент с `tabindex` ≥ 0; не входят `disabled`-элементы, `tabindex` < 0 и всё, что лежит внутри элемента с атрибутом `hidden`.
- Ловушка (на `keydown` документа, только для самого верхнего окна): `Tab` на последнем табулируемом – `preventDefault()` и
  фокус на первый; `Shift+Tab` на первом или на самом окне – фокус на последний. `Tab` в середине списка не гасится.
  Если табулируемых нет, `Tab` гасится и фокус остаётся на окне. Если фокус вне окна (например, на `body`), `Tab` гасится и
  фокус идёт на первый (с `Shift` – на последний) элемент.
- Если фокус программно уходит из верхнего окна наружу (`focusin` вне него), он возвращается на то место внутри окна, где
  был последний раз, а если такого нет – на окно.
- При закрытии фокус возвращается: на элемент, который был в фокусе в момент открытия (если это не `body` и он ещё в
  документе); иначе на `Trigger`, по клику на который окно открылось; иначе никуда не возвращается и ошибки нет.

## Закрытие

- `Escape` при открытом окне просит закрыть **только верхнее** окно (`onOpenChange(false)`); `preventDefault()` не обязателен.
- Клик ровно по `data-dialog-overlay` (не по содержимому окна) просит закрыть окно, кроме `role="alertdialog"`.
- В контролируемом режиме без обновления `open` окно остаётся открытым, фокус не двигается.

## Стек вложенных окон и фон

- Вложенное окно (его `Dialog` лежит внутри `Content` внешнего) открывается поверх: ловушка, `Escape` и возврат фокуса
  относятся только к верхнему окну; внешнее окно не отбирает фокус у вложенного. После закрытия вложенного фокус возвращается
  по правилу выше (как правило, на его `Trigger` внутри внешнего окна), и верхним снова становится внешнее.
- Пока открыто хотя бы одно окно, у каждого прямого потомка `document.body`, кроме элементов `data-dialog-overlay` самого
  верхнего окна, стоит `aria-hidden="true"` (в том числе у нижележащих окон). После закрытия состояние восстанавливается:
  атрибут, который был до открытия, остаётся как был, добавленные окном – снимаются.
- Пока открыто хотя бы одно окно, у `document.body.style.overflow` значение `hidden`; после закрытия последнего
  восстанавливается значение, которое было до открытия самого первого.
- Размонтирование открытого окна (или всего `Dialog`) снимает все эффекты: `aria-hidden`, `overflow`, обработчики
  документа; окно больше не реагирует на `Escape`.

## `DESIGN.md` (в корне репозитория)

Разделы `## Решения`, `## Компромиссы`, `## Границы применимости` – в каждом не меньше 200 символов: почему ловушка устроена
через `keydown` и `focusin`, а не через сторожевые элементы и `inert`; как устроен стек окон и что будет при гонке закрытия
вложенных окон; чем платим за портал в `body` (стили, серверный рендеринг, `z-index`); где контракт не покрывает
реальный браузер (видимость элементов, shadow DOM, iframe, мобильные скринридеры).

Видимые тесты – `tests/visible/` (`npx vitest run tests/visible`).
