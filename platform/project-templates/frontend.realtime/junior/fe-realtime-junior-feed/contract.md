# Контракт: лента сообщений в реальном времени (Junior)

TypeScript, без сторонних библиотек. Сеть в задаче не участвует: события приходят вызовами `apply`
(из WebSocket, SSE или опроса — ленте всё равно). События могут приходить повторно и не по порядку.

## `src/feed.ts`

```ts
export interface Message { id: string; author: string; text: string; sentAt: number; editedAt?: number }

export type FeedEvent =
  | { type: 'message'; message: Message }
  | { type: 'edit'; id: string; text: string; editedAt: number }
  | { type: 'delete'; id: string };

export interface Feed {
  apply(event: FeedEvent): void;
  messages(): Message[];
  unreadCount(): number;
  markRead(): void;
  subscribe(listener: () => void): () => void;
}

export function createFeed(options?: { me?: string }): Feed;
```

`sentAt` и `editedAt` — серверное время в миллисекундах.

### `apply`
- `message`: сообщение с новым `id` добавляется. Если сообщение с таким `id` уже есть или было удалено —
  событие игнорируется (повтор не перезаписывает текст, удалённое не воскресает).
- `edit`: у существующего сообщения меняется `text` и ставится `editedAt`, но только если `editedAt` события
  строго больше текущего `editedAt` сообщения (или правок ещё не было). Устаревшая правка игнорируется.
  Правка неизвестного `id` игнорируется и не запоминается.
- `delete`: сообщение убирается. `id` запоминается, даже если сообщения ещё нет: если `message` с этим `id`
  придёт позже, оно не появится. Повторное удаление безвредно.
- Некорректное событие бросает `TypeError`, состояние не меняется. Некорректно: не объект, неизвестный `type`,
  `id` не строка или пустая; у `message` — `author` или `text` не строки либо `sentAt` не конечное число;
  у `edit` — `text` не строка либо `editedAt` не конечное число.

### `messages()`
- Порядок: по `sentAt` по возрастанию, при равенстве — по `id` (сравнение строк оператором `<`), не по порядку прихода.
- Возвращает копии: изменение результата не влияет на ленту. У сообщения без правок поля `editedAt` нет.

### Непрочитанные
- Каждое добавленное сообщение считается непрочитанным, кроме сообщений автора `options.me`.
- `unreadCount()` — число непрочитанных сообщений, которые ещё в ленте: удаление непрочитанного уменьшает счётчик,
  правка и повтор — не меняют. `markRead()` обнуляет счётчик.

### `subscribe`
- `listener` вызывается синхронно после каждого события, которое изменило ленту (включая правки и удаления
  существующих сообщений), и после `markRead`, если счётчик был ненулевым. Игнорируемые события и `markRead`
  при нуле слушателей не дёргают.
- Возвращает функцию отписки; после неё `listener` не вызывается.
