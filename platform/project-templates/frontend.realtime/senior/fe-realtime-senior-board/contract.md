# Контракт: совместная доска, сходимость реплик при любом порядке доставки (Senior)

TypeScript, без сторонних библиотек, сети нет: операции передаются вызовами `apply` (WebSocket, SSE, опрос – репликам всё равно).
Каждый пользователь держит свою реплику доски. Сеть может доставлять операции **в любом порядке, повторно, с задержкой и пачками**.
Требование: когда все реплики получили все операции, их `snapshot()` совпадают, независимо от порядка и числа повторов.

## `src/board.ts`

```ts
export interface Stamp { c: number; r: string }   // Lamport-счётчик и id реплики

export type Op =
  | { kind: 'add'; id: string; title: string; column: string; ts: Stamp }
  | { kind: 'rename'; id: string; title: string; ts: Stamp }
  | { kind: 'move'; id: string; column: string; ts: Stamp }
  | { kind: 'remove'; id: string; ts: Stamp };

export interface Card { id: string; title: string; column: string }
export interface BoardStats { applied: number; duplicates: number; orphans: number }

export interface Replica {
  readonly id: string;
  add(title: string, column: string): Op;
  rename(cardId: string, title: string): Op;
  move(cardId: string, column: string): Op;
  remove(cardId: string): Op;
  apply(op: Op): void;
  snapshot(): Card[];
  log(): Op[];
  stats(): BoardStats;
  subscribe(listener: () => void): () => void;
}

export function createReplica(id: string): Replica;
```

### Время и порядок
- Метка `ts` = `{ c, r }`. Метка `a` новее метки `b`, если `a.c > b.c`, а при равенстве `a.r > b.r` (сравнение строк оператором `>`).
- Каждая реплика ведёт счётчик Lamport. Локальная операция получает `c = (наибольший c среди всех своих и принятых операций) + 1` и `r = id` реплики;
  для пустой реплики первая операция имеет `c = 1`. Принятая через `apply` операция сдвигает счётчик, поэтому следующая локальная операция новее любой принятой.

### Локальные операции
- Каждый из `add` / `rename` / `move` / `remove` применяет операцию к самой реплике, записывает её в `log()`, уведомляет подписчиков (если видимое
  состояние изменилось) и возвращает её – именно этот объект рассылается другим репликам.
- `add(title, column)` создаёт карточку с `id = "<id реплики>:<c>"`, где `c` – счётчик этой операции.
- `rename`, `move`, `remove` для неизвестной или удалённой у этой реплики карточки бросают `Error`; состояние и счётчик при этом не меняются.

### `apply(op)`
- Операция, не похожая на `Op` (не объект, неизвестный `kind`, нестроковые поля, `ts.c` не целое неотрицательное, `ts.r` не непустая строка), –
  `TypeError`; состояние не меняется.
- **Идемпотентность:** операция с тем же `kind`, `id` и `ts` повторно не меняет ничего и учитывается в `stats().duplicates`.
- **Любой порядок:** `rename` / `move` / `remove` может прийти раньше `add` той же карточки; результат тот же, что при обычном порядке.
  Такая карточка не видна в `snapshot()`, пока не пришёл её `add`, и считается в `stats().orphans`.
- `rename` и `move` – «последняя запись побеждает» по метке, **отдельно для каждого поля**: `title` и `column` независимы,
  параллельные `rename` и `move` одной карточки применяются оба. `add` задаёт начальные `title` и `column` со своей меткой `ts`
  (то есть более новый `rename` её перекрывает, а более старый – нет).
- `remove` окончателен: карточка не возвращается, поздние `rename` / `move` её не воскрешают, даже если их метка новее.

### `snapshot()`
Видимые карточки (был `add`, не было `remove`), по возрастанию метки их `add` (по `c`, затем по `r`). Каждый вызов возвращает новый массив
новых объектов.

### `log()`
Все принятые различные операции (локальные и полученные, без повторов), в порядке принятия, включая ещё «осиротевшие».
Новый массив при каждом вызове. Применение `log()` одной реплики к другой в любом порядке даёт им одинаковое состояние.

### `stats()`
`applied` – число принятых различных операций, `duplicates` – число отброшенных повторов, `orphans` – число карточек, для которых есть
операции, но нет `add`.

### `subscribe(listener)`
Слушатель вызывается после операции (локальной или принятой), если `snapshot()` реально изменился; повторы и операции над невидимыми
карточками его не вызывают. Возвращает функцию отписки, работающую сразу.

## `DESIGN.md` (в корне репозитория)

Три раздела второго уровня, каждый не короче 200 символов:
- `## Решения` – как достигнута сходимость и почему такая модель (метки, независимые поля, надгробие), как устроена идемпотентность;
- `## Компромиссы` – что отдано взамен: рост `log()` и надгробий, конфликты «последний победил» теряют правки, порядок только по создателю;
- `## Границы применимости` – когда модель не годится (текст внутри карточки, порядок внутри колонки, тысячи реплик) и что брать вместо неё.
