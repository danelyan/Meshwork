# Контракт: доска задач с серверным состоянием (frontend.ui-app, middle)

Модуль `src/TaskBoard.tsx` экспортирует компонент `TaskBoard({ api })`. Интерфейс API — `src/api.ts`
(файл платформы, не менять); проверка передаёт свою реализацию с управляемыми задержками и ошибками.
Окружение: Node.js 20, jsdom, React 19, Testing Library; без сети и своих зависимостей.

```ts
interface Task { id: string; title: string; done: boolean }
interface TasksApi {
  list(): Promise<Task[]>;
  create(title: string): Promise<Task>;
  setDone(id: string, done: boolean): Promise<Task>;
}
```

## Поведение (проверяется по ролям и подписям)

- **Загрузка.** Пока `list()` не ответил — `role="status"` с текстом **«Загрузка…»**.
- **Ошибка загрузки** — `role="alert"` с текстом **«Не удалось загрузить задачи»** и кнопка
  **«Повторить»**, которая снова вызывает `list()`.
- **Список.** Чекбокс на задачу, доступное имя чекбокса — название задачи, в порядке ответа сервера.
  Текст **«Осталось: N»** — число невыполненных.
- **Оптимистичное обновление.** Клик по чекбоксу сразу меняет его состояние и счётчик, затем вызывает
  `setDone(id, done)`. Ошибка — состояние откатывается, `role="alert"` **«Не удалось сохранить изменение»**.
  Пока запрос по задаче не завершён, её чекбокс выключен (`disabled`).
- **Создание.** Поле с подписью **«Новая задача»** и кнопка **«Добавить»** (форма, отправка и по Enter).
  Название обрезается по краям; пустое — текст **«Введите название»**, длиннее 120 символов —
  **«Не длиннее 120 символов»**, `create` в обоих случаях не вызывается. Пока `create` выполняется,
  кнопка выключена (повторной отправки нет). Успех — задача в конце списка, поле очищается. Ошибка —
  `role="alert"` **«Не удалось добавить задачу»**, введённый текст остаётся.
- **Фильтры** — кнопки **«Все»**, **«Активные»**, **«Готовые»** с `aria-pressed` у выбранной; по умолчанию «Все».

Видимые тесты — `tests/visible/`.
