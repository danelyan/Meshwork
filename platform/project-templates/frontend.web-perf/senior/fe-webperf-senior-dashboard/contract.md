# Контракт: дашборд с бюджетом рендеров и кэшем запросов (Senior)

React 19, TypeScript, без сторонних библиотек (TanStack Query, SWR, Redux и т. п. использовать нельзя — кэш пишете сами).
Проверка — vitest и Testing Library в jsdom. Время в тестах задаётся только функцией `now()`, которую получает кэш; реальные часы и
таймеры не используются. Размеры и layout в jsdom не считаются — на них контракт не опирается.

## `src/queryCache.ts`

```ts
export type Status = 'idle' | 'loading' | 'success' | 'error';
export interface Snapshot { status: Status; data: unknown; error: unknown }
export interface QueryCacheOptions {
  fetcher: (key: string) => Promise<unknown>;
  ttlMs: number;
  now: () => number;
}
export interface QueryCache {
  fetch(key: string, opts?: { force?: boolean }): Promise<unknown>;
  peek(key: string): Snapshot;
  subscribe(key: string, listener: () => void): () => void;
  invalidate(key: string): void;
  subscriberCount(key: string): number;
}
export function createQueryCache(options: QueryCacheOptions): QueryCache;
```

Каждый вызов `createQueryCache` создаёт независимый кэш.

### `fetch(key, opts?)`
- Если для ключа есть данные и они свежие (`now() - момент последней успешной загрузки < ttlMs`; ровно `ttlMs` — уже не свежие) и запись
  не помечена как устаревшая, `fetch` возвращает промис с кэшированными данными, `fetcher` не вызывается.
- Если запрос по ключу уже в полёте (и не был объявлен устаревшим через `invalidate`), `fetch` возвращает тот же результат без
  второго вызова `fetcher` (дедупликация), в том числе при `force: true`.
- Иначе вызывается `fetcher(key)` — синхронно внутри `fetch`, один раз. `force: true` обходит проверку свежести.
- Результат `fetch` — данные загрузки. Если `fetcher` отклонил промис или бросил исключение синхронно, `fetch` отклоняется с той же ошибкой.
  Ошибка не кэшируется: следующий `fetch` снова вызывает `fetcher`.

### `peek(key)`
- Возвращает снимок записи. Пока запись не менялась, **возвращается один и тот же объект** (это условие корректной работы
  `useSyncExternalStore`). Для ключа, который не загружали, — `{ status: 'idle', data: undefined, error: undefined }`.
- Первая загрузка: `idle` → `loading` (данных нет) → `success` с `data`. Повторная загрузка при уже имеющихся данных статус не меняет:
  в `success` остаётся прежний `data`, пока не придёт новый (stale-while-revalidate).
- Ошибка: `status: 'error'`, `error` — причина; ранее загруженные `data` не затираются. Повторная попытка после ошибки без данных
  переводит запись в `loading`, после успеха — в `success` с `error: undefined`.
- Структурное разделение: если новые данные равны прежним по содержимому (`JSON.stringify`), в снимке остаётся **прежняя ссылка**
  `data`, снимок не заменяется и подписчики не уведомляются.

### `subscribe(key, listener)` / `subscriberCount(key)`
- `listener` вызывается (без аргументов) каждый раз, когда снимок ключа заменился; ровно один раз на замену. Возвращаемая функция
  отписывает; после отписки `listener` не вызывается. `subscriberCount` — число активных подписчиков ключа.

### `invalidate(key)`
- Помечает запись устаревшей: следующий `fetch` пойдёт в `fetcher`, а прежние данные останутся в снимке до прихода новых.
  Неизвестный ключ — ничего не делает и не создаёт запись.
- Если запрос по ключу сейчас в полёте, он считается устаревшим: следующий `fetch` запускает **новый** запрос, а ответ старого
  в снимок не попадает, даже если придёт позже нового. Промис старого `fetch` при этом завершается своим результатом.
  Если ответ устаревшего запроса пришёл, а нового не было, он записывается в снимок, но запись остаётся устаревшей.

## `src/Dashboard.tsx`

```ts
export interface WidgetSpec { id: string; title: string; key: string }
export interface DashboardProps {
  cache: QueryCache;
  widgets: WidgetSpec[];
  onWidgetRender?: (id: string) => void;
}
export function Dashboard(props: DashboardProps): JSX.Element;
```

Данные любого ключа — объект `{ value: number }`. Виджеты с одним `key` делят один запрос.

### Разметка
- Корневой элемент имеет атрибут `data-compact` со значением `"true"` или `"false"` (изначально `"false"`).
- Кнопка «Компактный вид» с `aria-pressed` переключает режим (состояние хранит `Dashboard`); кнопка «Обновить всё» — см. ниже.
- Каждый виджет — `<section aria-label={title}>` с заголовком `<h2>`.
- Нет данных и идёт загрузка — внутри секции `role="status"` с текстом «Загрузка…».
- Есть данные — элемент с `data-testid="value"` и текстом `String(value)`; статуса «Загрузка…» нет, в том числе пока идёт
  повторная загрузка устаревших данных.
- Ошибка — `role="alert"` с текстом «Не удалось загрузить: {title}» и кнопка «Повторить», которая вызывает `cache.fetch(key, { force: true })`.
  Ошибка одного виджета не влияет на остальные; необработанных отклонений промисов быть не должно.

### Загрузка и подписки
- При монтировании данные запрашиваются через `cache.fetch(key)`: свежие данные в кэше запросов не порождают, на каждый уникальный
  ключ без свежих данных — один запрос. Виджет подписывается на **свой** ключ (`cache.subscribe`) и отписывается при размонтировании;
  ответ, пришедший после размонтирования, ничего не обновляет и не пишет в консоль.
- «Обновить всё»: для каждого уникального ключа `invalidate`, затем `fetch` — один запрос на ключ (в том числе если загрузка ещё в полёте).

### Бюджет рендеров
Вывод каждого виджета обёрнут в `<Profiler id={id} onRender={…}>` **внутри самого виджета**: для каждого коммита виджета вызывается
`onWidgetRender(id)`. Требования:
- от монтирования до получения данных — не более 3 коммитов на виджет; после этого коммит происходит только когда изменились
  данные или статус **его** ключа;
- приход данных одного ключа не вызывает коммитов виджетов других ключей;
- переключение «Компактный вид» не вызывает коммитов ни одного виджета;
- повторный рендер `Dashboard` с новым массивом `widgets` равного содержимого (новые объекты, те же `id`/`title`/`key`) не вызывает
  коммитов виджетов;
- «Обновить всё», вернувшее те же данные, не вызывает коммитов; если изменился ключ — по одному коммиту у виджетов этого ключа.
